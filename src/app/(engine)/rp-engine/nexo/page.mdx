# Moving from Nexo

RP Engine reads Nexo's current item YAML directly. Copy the `.yml` files from
`plugins/Nexo/items/<your-pack>/` into one RP Engine content pack (the normal
`items/` tree is accepted too), then copy
the **contents** of that pack's `assets/<your-pack>/` folder alongside them as
`assets/`.

```
plugins/RPEngine/content/
  my_pack/
    items/                    ← from Nexo/items/<your-pack>/
      weapons.yml
      furniture/chairs.yml
    assets/                   ← contents of Nexo's assets/<your-pack>/
      models/item/
      textures/item/
```

There is no conversion command and no `pack.yml` required. RP Engine recognises
the capital `Pack:` block that Nexo uses; its own item format uses lowercase
`model:` and `texture:`, so the two cannot be confused.

## What comes across

| Nexo | RP Engine |
| --- | --- |
| item id | an [item](/rp-engine/items) under the content folder's namespace |
| `material` | `material` |
| `itemname` | `name` |
| `Pack.model` | `model` |
| `Pack.texture` | `texture` |
| `Components.item_model` | `model` (for modern Nexo items that do not use `Pack:`) |
| `lore` | `lore` |
| `AttributeModifiers` | `attributes` (attribute, amount, operation and slot) |

An item model such as `my_pack:item/ruby` becomes RP Engine's `item/ruby` model
source. Its texture is copied with the assets, so the engine builds its own
item definition and does not inherit Nexo's CustomModelData allocation.

## Furniture and blocks

Nexo furniture becomes an RP Engine [`place:`](/rp-engine/models) item. Its
barrier hitbox becomes `solid: true`, the first `seats:` position (or a simple
seat height) becomes `seat:`, and a Nexo/Oraxen item drop becomes an RP Engine
`drop:`. The two plugins' display
transform, billboarding and culling settings are renderer settings, so they do
not transfer.

`Mechanics.custom_block` becomes an RP Engine [custom block](/rp-engine/blocks)
instead of a second item with the same ID. Its model, base family, hardness,
preferred tool and placement sound transfer. Nexo's allocated variation number
does not: RP Engine assigns and persists its own number.

## Recipes and glyphs

Copy Nexo's `recipes/` and `glyphs/` folders into the matching RP Engine
content pack. Recipe files named `shaped`, `shapeless`, `furnace`, `blasting`,
`smoking`, `campfire` or `stonecutting` are translated directly, including
vanilla ingredients and Nexo item results/ingredients. Static bitmap glyphs
become [icons](/rp-engine/icons), retaining their texture, height and ascent.

Animated GIF glyphs and multi-bitmap glyph grids intentionally report a
warning: they need generated frames or several allocated characters, neither
of which is a single RP Engine icon.

## What does not

The remaining `Mechanics` are Nexo plugin behaviour rather than a shared item
format. RP Engine loads the item or block and warns with its id and each
mechanic it skipped. Re-author click/script behaviour with
[actions](/rp-engine/actions).

HUDs, storage containers, connected furniture, beds/doors and text entities
are not imported yet. Those are stateful Nexo mechanics rather than one item
or bitmap definition.

<Callout type="warning" title="A Nexo world does not migrate">
  Existing Nexo blocks stay allocated to Nexo's own state scheme. This imports
  the item definitions and art, not blocks already placed in a world.
</Callout>
