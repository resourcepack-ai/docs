# Icons

An icon is a picture that behaves like a letter.

```yaml
# fonts/icons.yml
sword:
  file: sword     # assets/textures/font/sword.png
  height: 10
  ascent: 8
```

Put one into any text with `:mypack:sword:`.

Icons go into the game's **default font**, which is what makes them work
everywhere text does: chat, an item name typed at an anvil, a sign, a
scoreboard, a boss bar, the title of a GUI. Nothing has to know about RP Engine
to render one — by the time the text reaches the client it is a character like
any other.

## Height and ascent

`height` is how tall it is drawn, in pixels. `ascent` is how far above the text
baseline it sits.

An ascent equal to the height puts the icon's bottom edge on the line, which is
what you usually want. A smaller ascent drops it; a larger one lifts it. An
ascent **greater than the height** is refused by the client and the font fails
to load, taking every icon in it down — so this is the one number worth
checking.

Start with `height: 8, ascent: 7` to sit an icon in a line of chat, then adjust.

## A sheet of icons

A PNG of pictures in equal cells can be shared by several icons, each naming
its cell:

```yaml
smile:
  file: emotes                            # assets/textures/font/emotes.png
  grid: { rows: 2, columns: 4, cell: 3 }  # cells count from 1, left to right, then down
  height: 8
  ascent: 7
```

Nothing is cropped: the sheet ships once and the game's own font cuts it, so a
cell is exactly what was drawn. `height` and `ascent` are the cell's, not the
sheet's. The PNG's width has to divide by the columns and its height by the
rows.

## Store the ID, never the character

<Callout type="warning" title="Codepoints move">
  Icons are handed codepoints in ID order, so adding one shifts every icon
  after it. That is invisible to anything resolving an ID as it writes the text
  — and wrong for anything that saved the character into a config file, a
  database or a sign.

  `/rp icons` shows the character each icon became. It is there for debugging,
  not for copying into your configs.
</Callout>

## Using them

```
/rp icons              every icon, with what it became
/rp say :mypack:sword: sends yourself text with icons resolved
```

Anywhere your own config takes text, write the shortcode and RP Engine's API
will resolve it — see [the plugin API](/rp-engine/api).

Players can type them in chat too, if you turn that on:

```yaml
chat:
  icons: true
```

Then anybody with `rpengine.chat.icons` can type `:wave:` for the icon called
`wave`, or `:mypack:wave:` where two packs use one name. It is off by default,
and a name that is not an icon is left exactly as typed — so `10:30`, `:)` and
a URL all survive. See [Configuration](/rp-engine/config#icons-in-chat).

### More ways to type one, and who may

An icon can list other spellings, and can be kept for some players:

```yaml
heart:
  file: heart
  aliases: ["<3", ":love:"]       # also typed as these
  permission: mypack.icon.heart   # who may type it, by an alias or by :heart:
```

**An alias is matched as a word on its own**, with a space or the end of the
line on both sides. So `<3` becomes the heart in `I <3 you` and not in `<33`,
`a<3`, `<3!` or the end of a link. It is matched exactly as written,
punctuation and all, and cannot contain a space. When two icons list the same
alias, the first by ID keeps it and the load says so.

`permission` is on top of `rpengine.chat.icons`, not instead of it. Without
one, anybody who may use chat icons may use that icon. Somebody without it sees
what they typed go out as typed.

Both are about **typing in chat**. Your own plugin's text, resolved through
[the API](/rp-engine/api), takes `:namespace:id:` and ignores both, because a
config file is not somebody typing.

## Animated icons

An icon can have frames. Draw them as a **strip**, stacked top to bottom, every
frame the same size:

```yaml
loading:
  file: loading            # assets/textures/font/loading.png, 8 frames tall
  height: 9
  ascent: 8
  animation:
    frames: 8              # the PNG's height has to divide by this
    fps: 10                # 10 if left out; 1 to 20
    loop: true             # true if left out
```

Or hand it a **GIF**, and the build draws the strip for you:

```yaml
dance:
  gif: dance.gif           # assets/textures/font/dance.gif
  height: 11
  ascent: 9
```

A GIF plays at its own speed (the average of its frame delays) unless
`animation.fps` says otherwise, and `animation.frames` can keep only the first
few of its frames. It is read the way a browser plays it: each frame drawn onto
the one before at its offset, and cleared or put back as the file says. The GIF
itself does not ship; the strip beside it, `dance.gif.png`, is what players
download.

| Limit | Why |
|---|---|
| **64 frames** | Every frame is a character of its own, out of the 6,400 that icons, GUIs and HUDs share. A longer GIF keeps its first 64 and says so; a strip that claims more is drawn as its first frame |
| **20 fps** | Once a tick. Nothing the server sends changes faster than that |
| **256 pixels a side** | The game draws nothing for a glyph bigger than that, so a larger GIF frame is scaled down to fit, with a warning |

`animation:` is for a strip or a GIF, not a `grid:` sheet.

### Where it moves, and where it does not

The server animates an icon by sending the next frame's character, so an icon
moves only in text that is **sent again as time passes**:

- a scoreboard, a tab list, a hologram or a menu that shows
  `%rpengine_icon_mypack:dance%` through
  [PlaceholderAPI](/rp-engine/placeholderapi). Each refresh asks again and gets
  the frame showing now, so it moves as fast as that plugin refreshes;
- a plugin's own text, redrawn through [the API](/rp-engine/api).

It does **not** move in anything sent once. A chat message, an item name, a
sign, a book, a dialog, `/rp say`: those are drawn once and show the **first
frame** for good. `:mypack:dance:` typed in chat is the first frame.

<Callout type="note" title="Why chat shows the first frame">
  Nexo and Oraxen animate a glyph in the client instead, with a replacement for
  the game's text shader that recognises a special colour and flips through the
  frames itself. That moves everywhere, chat included.

  RP Engine does not ship a text shader, because a pack can carry only one, and
  other packs sent to the same players (ResourcePack AI Studio's among them)
  already replace that shader for their own overlays. Whichever pack was on top
  would silently break the other's, and the one that lost would look like a bug
  nobody could find. Picking frames on the server cannot collide with anything.
</Callout>

A frame's width is how far the text after it moves along, and the game
measures it to the last pixel drawn in that frame. So a frame narrower than the
others nudges what follows it. If that matters, draw every frame across the
same width: a pixel in the far column at the lowest alpha you can save is
enough.

`loop: false` plays once and stays on the last frame, **timed from when the
server started**. There is no moment a frame-picking server can call "when you
looked", so a one-shot icon has played by the time most people see it. It is
there for an icon that should settle (a fill that ends full) rather than for an
effect.
