# Dialogs

A dialog is a menu the server opens on a player's screen, in Minecraft 1.21.6
and newer: a title, some text, and buttons that run commands. Use one for a
welcome screen, a warp menu, a settings page or a staff tool. Unlike a
[screen](/rp-engine/screens), it isn't a chest wearing a picture; the game draws
real buttons.

![A settings dialog open in game](/images/dialogs.webp)

## Making one

Write it in a `dialogs/` folder of your [content folder](/rp-engine/content):

```yaml
# mypack/dialogs/menus.yml
welcome:
  title: Welcome
  body:
    - Glad you made it.
    - Pick somewhere to start.
  columns: 2                       # how many buttons sit side by side
  buttons:
    - label: Spawn
      command: spawn               # the PLAYER runs it, with their permissions
      tooltip: Back to the middle
    - label: Shop
      console: warp shop {player}  # the CONSOLE runs it: no /warp for players
    - label: The wiki
      url: https://example.com
```

Run `/rp reload`, then `/rp dialogs` lists them and `/rp dialog mypack:welcome
[player]` opens one.

<Callout title="RP Engine or Dialog Engine?">
  [Dialog Engine](/dialog-engine) is a separate plugin for dialogs only. The two
  don't share dialogs: a dialog written here opens with `/rp dialog`, and one
  written for Dialog Engine opens with `/de open`. Use RP Engine's if you already
  run RP Engine; use Dialog Engine if dialogs are all you need, or you want its
  inputs and click events.
</Callout>

## What a button does

Each button does one thing, named by its key:

| Key | What happens on a click |
|---|---|
| `command:` | The player runs the command, with their own permissions |
| `console:` | The console runs it, with `{player}` filled in for whoever clicked |
| `suggest:` | The command is typed into their chat box, not sent |
| `url:` | Opens a link (the game asks first) |
| `copy:` | Copies the text to their clipboard |
| `dialog:` | Opens another dialog by its id |
| none | Just closes the dialog, like an Ok button |

A button also takes `label:` (default "Ok"), `tooltip:` and `width:` (default
150). One button makes a notice, two a yes/no, three or more a grid.

**`console:`** is for a command a player should only get from the dialog, such
as a warp they can't type. Typing it in chat does nothing, and nobody can change
a word of it. A button pressed twice runs twice, so for something given once,
check first or close the dialog after it.

**Several commands on one button**: give `command:` or `console:` a list, up
to 16. They run in order and stop at the first that fails.

```yaml
    - label: Starter kit
      console:
        - give {player} bread 8
        - give {player} torch 16
    - label: Go
      command: [spawn, "kit starter"]   # the PLAYER runs both
```

## Opening it with a command of its own

```yaml
shop:
  command: shop                    # /shop opens it on whoever types it
  permission: myserver.shop        # optional
  title: Shop
```

If another plugin already has `/shop`, that plugin keeps it and the console
says so.

## Dialogs about somebody

Write `{target}`, or any name, anywhere a dialog has words or a command, and
give it a value when you open it:

```yaml
punish:
  title: Punish {target}
  buttons:
    - label: Mute 1h
      command: mute {target} 1h
```

```
/rp dialog mypack:punish target=Steve Admin
```

opens it for Admin, titled "Punish Steve". `{player}` and the other
[built-ins](/rp-engine/hud#live-values-in-text) describe whoever the dialog is
shown to, and PlaceholderAPI answers the rest when it is installed.

## Settings per player

Declare settings under `vars:` with every value they may take, and a button
changes one with `/rp var`:

```yaml
settings:
  title: "Sidebar: {show_sidebar?off:Hidden|on:Shown}"
  vars:
    show_sidebar: ["on", "off"]
  buttons:
    - label: "Turn it {show_sidebar?off:on|on:off}"
      command: "rp var show_sidebar {show_sidebar?off:on|on:off}"
```

`{name?value:words|...}` picks the words for the player's value, and the last
entry when none matches. Settings survive restarts, and other plugins read them
as `%rpengine_var_show_sidebar%`. Quote `on`, `off`, `yes` and `no`, or YAML
reads them as true and false.

## Pages

Make each page a dialog of its own and turn between them with `/rp page`:

```yaml
settings:
  title: Settings
  after: none                      # stay up until the next page replaces it
  buttons:
    - label: Audio
      command: rp page mypack:settings_audio
    - label: Close
      command: rp page close
```

A player can only reach a page through a button that runs exactly that
command. After a server restart, page turns happen instantly on the client.

## What happens after a click

`after:` decides:

| Value | What the player sees |
|---|---|
| `seamless` (default) | The dialog stays up until the server has answered, so a dialog the click opens replaces it with no flicker |
| `close` | Closes at once |
| `none` | Stays open. It is drawn again after a `console:` button or a command list runs, so changed values show |
| `wait_for_response` | The game's "waiting for response" screen |

`can_close_with_escape: false` stops Esc closing it (a dialog with no buttons
always closes with Esc). `pause: true` pauses a single-player world, and only
works with `close` or `wait_for_response`.

## Click sounds

The game makes no sound for a click on a dialog's picture, so RP Engine plays
one. Choose your own per dialog or per command:

```yaml
shop:
  click-sound: { sound: block.note_block.chime, volume: 0.5, pitch: 1.5 }
  click-sounds:
    - { command: "buy {item}", sound: "" }   # this click is silent
```

## On the Quick Actions key (G)

Minecraft 1.21.6 added a Quick Actions key, G by default. `quick-action:` puts a
dialog on it; with several, G shows a list.

```yaml
hub:
  title: "Hub for {player}"
  quick-action: true             # G opens the dialog itself (Paper only)
warps:
  title: Warps
  quick-action:
    mode: launcher               # G opens a button that opens it fresh
    label: Warps                 # its name in G's list
```

The key opens a copy the player received as they joined, so with `true` its
placeholders show what was true at join time. `launcher` opens a one-button
screen instead, whose button opens the dialog fresh. Spigot, and any dialog with
a `permission:` or the player's items in it, always uses the launcher. **A
change takes a server restart**, and the console says when one is due.

## Reacting to a click in your own plugin

RP Engine has no "button clicked" event: a button runs a command, so register
that command in your plugin and handle it there. To change what a dialog shows,
set values from code with `dialogs().set(...)` and open it again. See
[Dialogs in the API](/rp-engine/api#dialogs). Moving an item in a Studio dialog's slots
fires `DialogSlotMoveEvent`, which you can cancel.

## Dialogs from Studio

A [dialog made in Studio](/dialogs) arrives when you push the pack to your
server (see [Testing on your server](/testing/plugin)), with the id `studio:<id>` (and
`studio:<id>.<page>` for its pages), drawn in Studio's art. Everything above is
set in Studio's editor instead: live values, settings on switches and sliders,
pieces shown only to some players ("Show when"), item slots, live progress
bars, player heads and click sounds. RP Engine fills each in for the player it
is shown to.

A dialog exported from Studio as a JSON file works without a push too:

```yaml
shop:
  json: mypack/dialogs/shop.json   # path inside the content folder
```

The same `json:` key takes any `minecraft:dialog` file you wrote yourself, for
anything the keys on this page can't say.

## Versions

A dialog needs **Minecraft 1.21.6**. On an older server the definitions still
load and `/rp dialogs` says why nothing opens. A [screen](/rp-engine/screens) is
the older way to make a menu and works on every version.
