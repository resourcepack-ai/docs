# Items

A custom item is a vanilla item with your own name, texture or 3D model on it.
Because it is a real vanilla item underneath, it stacks, burns in lava, goes in
a hopper, and every other plugin sees an ordinary item. Furniture, vehicles
and armour all start as items.

Items are written in YAML files in the `items/` folder of your pack inside
`plugins/RPEngine/content/` (your [content folder](/rp-engine/content)). One
file can hold as many as you like.

![Custom items in an inventory](/images/items.webp)

```yaml
# items/gems.yml
ruby:
  material: DIAMOND        # required: the vanilla item underneath
  name: "&cRuby"
  lore: ["&7Warm to the touch."]
  texture: item/ruby       # defaults to item/<id>
  stack: 16                # largest stack
  glow: true               # the enchanted shimmer, without an enchantment
  unbreakable: true
```

`material` decides how the item behaves, so pick it for that. A `PAPER` ruby
does nothing when used; a `DIAMOND_SWORD` one swings like a sword. Names and
lore take `&` colour codes.

`/rp give mypack:ruby` gives you one. `/rp items` lists them all, and
`/rp item menu` opens them in a chest to take from.

`stack` and `glow` need Minecraft 1.20.5 or newer; on an older server they are
ignored with a console warning.

## The texture

With no `texture:` and no `model:`, `mypack:ruby` uses
`assets/textures/item/ruby.png`. `texture:` points somewhere else, for example
to let two items share one picture. It can also be a full resource location,
such as `minecraft:item/custom/ruby`.

A missing texture is a build warning that names the path it looked for.

## 3D items

Point `model:` at a Blockbench file in `assets/models/`:

```yaml
sword:
  material: IRON_SWORD
  model: sword             # assets/models/sword.bbmodel
```

Two file types work:

- **`sword.bbmodel`**: the project Blockbench saves. Its textures are inside
  it, so the model is one file. Use this one.
- **`sword.json`**: a Java model exported from Blockbench, with its PNGs beside
  it. It has no bones or keyframes, so [an animated model](/rp-engine/animation)
  must be the `.bbmodel`.

The game's models only allow a cube to be rotated on one axis, by -45, -22.5,
0, 22.5 or 45 degrees, so other rotations are snapped to the nearest of those.
Meshes are left out: convert them to cubes first.

`model:` can also name a model by resource location
(`model: minecraft:item/custom/lamp`), or be written into the item directly:

```yaml
pick:
  material: IRON_PICKAXE
  model:
    parent: minecraft:item/handheld
    textures: { layer0: mypack:item/pick }
```

### A different model in first person

`first-person:` is a second model, written any of the same ways as `model:`,
that is drawn only in the holder's own first-person view. Everyone else, and
the inventory, see `model:`. It suits an aimed gun, where the sights should
fill the view:

```yaml
rifle_aimed:
  material: PAPER
  model: rifle
  first-person: rifle_sights
```

Needs Minecraft 1.21.4 or newer. On an older server the normal model is used in
first person too, with a warning.

### An icon in the inventory

`gui:` is how the item looks in an inventory slot: the hotbar, a chest, a
creative tab. A model made to be seen in the world, like a vehicle or a chair,
is hard to read shrunk to sixteen pixels, so give it an icon instead. Write a
model the same ways as `model:`, or `{texture: ...}` for a flat icon (a bare
name is looked for in `textures/item/`):

```yaml
red_kart:
  material: PAPER
  model: red_kart
  gui: {texture: red_kart_icon}
```

Everywhere else (in a hand, on the ground, placed) the item keeps its model.
Needs Minecraft 1.21.4 or newer, like `first-person:`.

It works on 3D armour pieces too: an item with `armor3d:` and `gui:` shows the
icon in the slot and the 3D piece everywhere else, on the player included.

### Bows and crossbows: drawing back and loaded

A custom bow or crossbow can change look as it is drawn and when it is loaded,
like the vanilla ones. `pull:` gives the item a look for each stage of being
drawn, the way a vanilla bow has three. The first is shown the moment the player starts drawing, and
the item goes back to its own look when they let go:

```yaml
longbow:
  material: BOW
  model: longbow
  pull: [longbow_pull_0, longbow_pull_1, longbow_pull_2]
```

Each entry is the same kind of thing as the item's own look: a model when the
item has a `model:`, a texture when it is a flat sprite (a bare name such as
`longbow_pull_0` is `textures/item/longbow_pull_0.png`). To mix them, or to
say when each stage starts, write each one out:

```yaml
pull:
  - { at: 0,    model: longbow_pull_0 }
  - { at: 0.65, texture: item/longbow_pull_1 }
  - { at: 0.9,  model: longbow_pull_2 }
```

`at:` is how far drawn the stage begins. A bow is fully drawn after one second,
so for a bow it reads as a fraction; a crossbow's is the fraction of its loading
time, so Quick Charge speeds the stages up as it does vanilla's. Leave it out
and three stages on a bow or crossbow use vanilla's own timings, and any other
number of stages is spread evenly.

A crossbow also has a loaded look:

```yaml
repeater:
  material: CROSSBOW
  model: repeater
  pull: [repeater_pull_0, repeater_pull_1, repeater_pull_2]
  charged: repeater_arrow            # loaded with an arrow
  charged-firework: repeater_rocket  # loaded with a firework; optional
```

Without `charged-firework:` a firework shows the `charged:` look too.

All of it is drawn by the player's own game, so everybody watching sees the
draw and the server sends nothing while it happens. On Minecraft 1.21.4 or
newer any item a player can hold in use (a bow, a crossbow, a trident, a
shield) can have `pull:` stages. On an older server only an item built on
`BOW` or `CROSSBOW` can, and anything else keeps its own look, with a warning.
Bedrock players see the item's own look throughout. Needs RP Engine 0.2.25 or
newer.

Drawing, loading, first person and the inventory icon are the only things an
item's look can follow. For an item that changes for another reason (a lamp
switched on, a Christmas version), make a second item; a placed piece can use
[states](/rp-engine/furniture#states-lamps-doors-and-screens) instead.

## Tools made of parts

An item can be built out of parts that a player chooses, like a pickaxe made
of a handle and a head. You make one small item per part, and RP Engine draws
the tool out of whichever parts it holds. Four handles and four heads are eight
textures, not sixteen whole pickaxes.

```yaml
oak_handle:
  material: STICK
birch_handle:
  material: STICK
iron_head:
  material: PAPER
gold_head:
  material: PAPER

pickaxe:
  material: IRON_PICKAXE
  name: Pickaxe
  parts:
    handle: [oak_handle, birch_handle]
    head: [iron_head, gold_head]
```

- Each slot under `parts:` lists the items that can fill it. A name without a
  namespace is in the item's own pack.
- Slots are drawn in the order you write them, so a later slot is drawn over
  an earlier one where they overlap. Draw each part's texture in the place it
  takes in the finished tool, on a transparent background.
- A pickaxe that has not been given any parts (from `/rp give`, say) holds the
  first option in each slot: here, an oak handle and an iron head.
- The pickaxe needs no texture or model of its own.

To let players put one together, write a [recipe](/rp-engine/recipes#tools-made-of-parts)
whose ingredients are the parts. Plugins can set the parts themselves through
the [API](/rp-engine/api).

<Callout type="note" title="Minecraft 1.21.4 or newer">
  Drawing an item out of several models arrived in 1.21.4. On an older server
  the item draws as its own texture or model whatever parts it holds, and the
  parts are still kept on every stack.
</Callout>

## Borrowing another item's model

```yaml
ruby_sword:
  material: IRON_SWORD
  copy-model: mypack:sword
```

The item wears `mypack:sword`'s model without a copy of the files, which suits
a set of items that look alike and behave differently.

## Permissions

```yaml
wand:
  material: STICK
  permission: mypack.wand
```

Checked when the item is **used** (clicked, or placed if it is furniture), not
when it is given or held. A player without it is told "You cannot use that."
See [Permissions](/rp-engine/permissions#letting-players-use-your-items).

## The creative inventory

Custom items don't appear in the creative inventory's tabs or its search. The
game builds those from its own list of vanilla items, and a server can't add
to them. To pick custom items from a menu, run `/rp item menu`: a chest of
every custom item, click for one and shift-click for a stack. It needs
`rpengine.item`, which only ops have unless you grant it.

A player in creative mode can copy any item they can see in their own
inventory, a custom one included, and RP Engine doesn't prevent it. Keep
creative mode from players who mustn't have your items, rather than relying on
them not finding one.
