# Adding a resource pack

RP Engine sends your players one pack. So an existing resource pack, whether
you exported it from Studio or downloaded it, goes **into** that pack rather
than beside it.

## Putting a zip on your server

<Steps>
  <Step title="Drop the zip into content/">
    ```
    plugins/RPEngine/content/
      My Pack.zip
    ```

    Leave it zipped. Do not put it in `resourcepacks/` or your
    `server.properties`: RP Engine serves it for you.
  </Step>
  <Step title="Reload">
    Run `/rp reload`, or restart. Everybody online is sent the new pack.
  </Step>
</Steps>

On reload the zip is unpacked into a folder named after it, and the zip is
moved out of the way:

```
plugins/RPEngine/content/
  my_pack/                 ← the zip, unpacked
    pack.mcmeta
    assets/
plugins/RPEngine/unpacked-zips/
  My Pack.zip              ← moved here
```

From then on the folder is the pack: edit it there.

## A pack exported from Studio

A Java pack exported from [Studio](/exporting) goes in exactly as above. It
brings its shader objects, dialogs, screens and sounds with it: after
`/rp reload`, `/rp shaders` lists its [shader objects](/shaders) (Studio's
overlays drawn by a core shader) and `/rp shader studio:<id>` shows one. Their
rules (Always, On join and so on) apply to every player.

That needs RP Engine 0.2.38 or newer and a zip exported on or after 29 October
2026. An older zip still works as art, but its shader objects are not listed:
export it again.

<Callout type="note" title="Updating a Studio pack often?">
  [`/rp distribute`](/distribution) does this for you: the pack you publish in
  Studio is kept in `content/studio-<pack>/` and replaced on each release, with
  no zips to copy. To try a pack on yourself first, use
  [`/rp sync`](/rp-engine/commands#studio).
</Callout>

## Updating it

A zip is never unpacked over a folder that already exists, because that folder
might be one you have edited. To replace a pack with a new version, delete its
folder and drop the new zip in. Until you do, the console says the zip was
skipped.

## What gets copied

Everything, as written: every namespace (`minecraft` included), shaders,
sounds, fonts and language files. If its `pack.mcmeta` lists **overlays**
(folders only some game versions load), they come too, as do its `filter` and
`language` sections. Its `pack.png` becomes the icon unless another pack's
comes first alphabetically.

A resource pack defines no items or commands. It is art that rides along with
the rest of your content.

<Callout type="warning" title="Two packs replacing the same file">
  A resource pack can replace vanilla files, so two of them can disagree. The
  pack whose folder comes later alphabetically wins, and the build names both.
  Core shaders are the usual case: a player's game keeps one copy of each, so
  if another plugin's pack replaces the same shader, only one draws. See
  [Other plugins' shaders](/rp-engine/config#other-plugins-shaders).
</Callout>

## Unzipping it yourself

A folder in `content/` with `pack.mcmeta` and `assets/` at the top and no
`pack.yml` is read as a resource pack. Two things catch people out:

- **The folder name has to be a namespace**: lowercase letters, digits, `_`,
  `.` and `-`. `My Shaders` is refused; `my_shaders` works. (A zip is renamed
  for you.)
- **`pack.mcmeta` has to be at the top.** A zip that puts everything inside
  one folder is unwrapped for you; a folder you unzipped yourself is not. If
  the console says `No pack.yml, so this is not a content pack`, this is
  usually why.

## With your own content

To keep a resource pack and your own items in one folder, put the resource pack
inside a content pack as `resourcepack/`:

```
plugins/RPEngine/content/
  mypack/
    pack.yml
    items/
    resourcepack/          ← copied as written, overlays included
      pack.mcmeta
      assets/
```

This is the layout [CraftEngine](/rp-engine/craftengine) packs use, and works
exactly the same way.
