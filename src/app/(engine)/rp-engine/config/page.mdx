# Configuration

The settings live in `plugins/RPEngine/config.yml`, which the plugin writes
the first time it starts. Every setting has a working default. The one most
servers need to change is `host.public-address`, so players outside your
network can download the pack. Many settings apply on `/rp reload`; restart
the server to be sure a change has taken effect.

## Serving the pack

```yaml
host:
  port: 8181
  public-address: "http://127.0.0.1:8181"
  enabled: true
```

The plugin serves its built packs over HTTP itself.

| Key | Default | What it does |
|---|---|---|
| `host.port` | `8181` | The port it listens on. `0` picks a free one, which is only useful for testing |
| `host.public-address` | `http://127.0.0.1:8181` | The address a player's game downloads the pack from. Set it to your server's public IP or hostname and the port above, and open that port. The plugin cannot work this out itself behind a proxy or NAT |
| `host.enabled` | `true` | `false` if you host the built zips yourself (a CDN, a web server) and only want the plugin to build them |

## The pack and the join prompt

```yaml
pack:
  description: "RP Engine"
  # format: 46
default-bundle: "main"
prompt:
  message: ""
  force: false
```

| Key | Default | What it does |
|---|---|---|
| `pack.description` | `RP Engine` | Shown in the client's resource pack list, with the bundle name added |
| `pack.format` | not set | Leave it unset; the plugin picks the right number for your version. Set it only when the startup log says your Minecraft is newer than this RP Engine, then update the plugin and remove it. See [Minecraft versions](/rp-engine/versions#the-pack-format) |
| `default-bundle` | `main` | The [bundle](/rp-engine/bundles) every joining player is sent. Empty sends nothing, for a server that sends packs itself |
| `prompt.message` | empty | Text shown when the client asks the player to accept the pack. Empty uses the game's own wording |
| `prompt.force` | `false` | `true` disconnects a player who declines the pack |

## How it talks

```yaml
chat:
  icons: false
  prefix: "RPEngine"
  colour:
    prefix: "#3670f8"
    brackets: "#555555"
    body: "#aaaaaa"
    accent: "#3670f8"
    error: "#ff5555"
    success: "#55ff55"
```

Every line the plugin writes starts with `[prefix]`, and the colours are
yours to change so it matches your server. `accent` colours names, counts and
codes, and the headings in `/rp` help. Colours are hex, with or without the
`#`; anything else falls back to the default.

## Icons in chat

`chat.icons: true` lets anybody with `rpengine.chat.icons` (every player, by
default) type `:wave:` in chat to draw the [icon](/rp-engine/icons) called
`wave`. Use `:mypack:wave:` where two packs use the same name. It is off by
default.

Text that is not an icon name is left exactly as typed, so `10:30`, `:)` and
links are safe.

## Emotes

```yaml
emotes:
  player-commands: true
  bake-on-join: true
  rigs: true
  cast-permission: "rpengine.emote.cast"
  nametag-see-through: false
  held-item-pitch: 90.0
  held-item-yaw: 0.0
  held-item-roll: 0.0
```

An emote plays on a rig: a copy of the player's skin, cut into parts, which is
part of the pack.

| Key | Default | What it does |
|---|---|---|
| `player-commands` | `true` | Registers `/emote`. Turn it off if another plugin already has `/emote`; `/rp emote` still works, and `/emotereply` is always registered |
| `rigs` | `true` | Builds a rig for every player who has joined, plus a shared default, so emotes and vehicle seats work without Studio. Needs Minecraft 1.21.4 or newer |
| `bake-on-join` | `true` | Rebuilds the rigs when somebody joins who has none yet. See below |
| `cast-permission` | `rpengine.emote.cast` | The node needed to pull other players into an emote. Empty for no check |
| `nametag-see-through` | `false` | Whether an emoting player's name shows through walls. Off, because a see-through name tends to vanish behind nearby models |
| `held-item-pitch`, `-yaw`, `-roll` | `90`, `0`, `0` | Calibration for how a held item is turned in a rig's hand. You should not need these; if a held item looks wrong, please report it |

**What `bake-on-join` does.** A player the server has never seen has no rig,
so they appear as the default skin until the rigs are rebuilt. With this on,
the rebuild starts as soon as they join, and anybody else arriving within a few
seconds is covered by one follow-up build. Players who are already online are
not sent the new pack straight away (a new pack reloads their screen): they
get it the next time they are sent a pack anyway, such as on rejoining or with
`/rp push`. Until then they see the newcomer as the default. Turn it off to
choose the moment yourself; `/rp reload` always includes every rig that has
arrived.

## Seats

```yaml
models:
  seat-offset: 0.0
```

Moves every seat on placed models up or down, in blocks. Positive is higher.
If everybody sits slightly too high or low on every chair, set the difference
here and `/rp reload`. You should not need it.

## Vehicles

```yaml
vehicles:
  seat-offset: 0.0
  seat-forward: 0.0
  debug-seats: false
  push-players: false
  collide: true
  speedometer: true
  mount-hint: true
  seat-rig: true
```

| Key | Default | What it does |
|---|---|---|
| `seat-offset` | `0.0` | Moves every [vehicle](/rp-engine/vehicles) seat up (positive) or down, in blocks |
| `seat-forward` | `0.0` | Moves every vehicle seat toward the front (positive) or back |
| `debug-seats` | `false` | Once a second, reports where each rider actually ended up against where the plugin put them. For tracking down one seat that is out while others are fine |
| `push-players` | `false` | Whether a moving vehicle shoves players out of the way. Mobs are always shoved, and vehicles always stop at walls |
| `collide` | `true` | Whether vehicles bump into each other. The result depends on speed, angle and each vehicle's weight. Turn it off for a race track or a crowded car park |
| `speedometer` | `true` | Shows the driver's speed above the hotbar in km/h, yellow while the tyres slide. A single vehicle can opt out; see [the speedometer](/rp-engine/vehicles#the-speedometer) |
| `mount-hint` | `true` | Tells somebody the controls once when they get in. Passengers are told which seat they took either way |
| `seat-rig` | `true` | Shows occupants sitting or standing in their emote rig, even when the pack gives the seat no emote. Off shows ordinary players, which costs fewer entities on a full vehicle |

Which controls a vehicle uses depends on your server: Paper 1.21.4 and newer
reads the movement keys, anything else steers by where the driver looks. See
[Minecraft versions](/rp-engine/versions).

## Plants

```yaml
blocks:
  tripwire-frozen: auto
```

How many [plants](/rp-engine/blocks#plants) fit depends on whether Paper has
frozen tripwire updates (`block-updates.disable-tripwire-updates` in
`config/paper-global.yml`): 32 if it has, 2 if not. `auto` reads Paper's
setting. `true` or `false` states it outright, for a server whose Paper config
lives somewhere else. Saying `true` when tripwire is not frozen makes
neighbouring plants turn into each other.

## Dialogs

```yaml
dialogs:
  click-sound: "ui.button.click"   # blank for none
  click-volume: 0.25               # 0 to 1
  click-pitch: 1.0                 # 0.5 to 2
```

A click on a dialog's picture makes no sound in the game, so the plugin plays
this one. Any sound event works, the game's or one your pack adds. A Studio
dialog can choose its own [click sound](/dialogs#click-sounds), for the whole
dialog or one piece, and that takes priority. A hand-written dialog can too:

```yaml
shop:
  json: shop.json
  click-sound: { sound: block.note_block.chime, volume: 0.5, pitch: 1.5 }
  click-sounds:                      # the clicks that run this command
    - { command: "rp page mypack:shop.ranks", sound: entity.experience_orb.pickup }
```

`click-sound: ""` silences a dialog's clicks.

## Studio

```yaml
sync:
  url: "wss://sync.resourcepack.ai/connect"
  server-token: ""
edit:
  enabled: true
  url: "https://studio.resourcepack.ai"
distribution:
  api-url: "https://studio.resourcepack.ai"
```

Nothing connects to Studio unless somebody runs `/rp sync`, `/rp edit` or
`/rp distribute`. Leave the URLs alone.

| Key | Default | What it does |
|---|---|---|
| `sync.server-token` | empty | Only for a server the Studio account owner runs themselves. With a token, Studio can see who is online and push to them without a pairing code |
| `edit.enabled` | `true` | `false` turns off [`/rp edit`](/rp-engine/editing) |

## Usage count

```yaml
telemetry:
  enabled: true
```

Every 30 seconds the plugin tells resourcepack.ai it is running, so we know
how many servers and players use RP Engine and its addons. It sends three
things: a random id it created the first time it started (kept in
`plugins/RPEngine/server-id`; delete the file and a new one is made), the
number of players online, and the names of installed plugins that depend on
RP Engine. No address, server name, version, player names or UUIDs, worlds or
content. A failed send is silently dropped.

`enabled: false` sends nothing at all, from the next restart.

## Update check

```yaml
update-check: true
```

Tells the console at startup, and players with `rpengine.update` (ops) when
they join, that a newer RP Engine is out.
