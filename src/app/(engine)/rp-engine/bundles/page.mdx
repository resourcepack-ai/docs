# Bundles

A **bundle** is one built resource pack. Most servers have one, called `main`,
and never think about it.

```yaml
# in a pack's pack.yml
bundles: [main]
```

```yaml
# in config.yml
default-bundle: main     # what every joining player is sent; empty sends nothing
```

`/rp bundles` lists them with their sizes and hashes.

A content pack lists the bundles it belongs to (`main` if it says nothing),
and a bundle can hold many packs. One pack can be in several bundles, which is
how a shared base pack gets into every bundle without being copied.

## More than one at a time

From Minecraft 1.20.3 a server can add and remove resource packs per player.
So a lobby can use one bundle, a dungeon another, and an event pack can sit on
top of whatever a player already has.

Two rules come from the game itself:

- **A later bundle overrides an earlier one** where both change the same file.
- **A bundle the player already has downloads nothing.** Swapping back to it
  is instant.

Below 1.20.3 a player holds one pack at a time, so a player due more than one
bundle gets only the last. A server with a single bundle is unaffected.

## Rebuilding changes nothing unless the content did

The same content always builds to exactly the same zip. The client recognises
a pack it already has by its hash, so a restart or a reload that changes
nothing makes nobody download anything.

## Serving them

By default the plugin uploads each built pack to ResourcePack AI's pack host
and sends players the link to it, so there is nothing to open or configure.
It can serve them from your own server instead, on the game port or a port of
its own, or leave hosting to you. See
[Configuration](/rp-engine/config#serving-the-pack).
