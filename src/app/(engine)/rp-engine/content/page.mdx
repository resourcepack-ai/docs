# The content folder

Everything you add lives in `plugins/RPEngine/content/`, one folder per pack.
The folder name is the pack's [namespace](/rp-engine/ids): lowercase letters,
digits, `_`, `.` and `-`.

```
plugins/RPEngine/content/
  mypack/
    pack.yml               required
    items/       *.yml
    sounds/      *.yml
    fonts/       *.yml
    screens/     *.yml
    huds/        *.yml
    dialogs/     *.yml
    recipes/     *.yml
    entities/    *.yml
    liquids/     *.yml
    blocks/      *.yml
    vehicles/    *.yml
    emotes/      *.json or *.yml
    armor3d/     *.yml      3D armour sets
    objects/     *.yml      3D shader objects and their sequences
    assets/                → assets/mypack/ in the built pack
      textures/
      models/              Blockbench files
      sounds/
    overrides/             → assets/minecraft/, for replacing vanilla art
    pack.png               optional
```

## The rules

**The category folder decides the kind.** Top-level keys in a file are ID
paths, so you do not nest them under an `items:` key. One file can declare
many things, the file name does not matter, and subfolders are only for your
own organisation: `items/weapons/swords.yml` adds nothing to the ID.

**Only the folders above are read.** There is no `models/` folder: a placed
model is a [`place:` block on an item](/rp-engine/models). Any other folder is
warned about by name, which catches typos like `item/` and `Sounds/`. Other
plugins' layouts are the exception and are read where they are: see
[Model Engine](/rp-engine/modelengine) and [BetterModel](/rp-engine/bettermodel).

**A mistake skips one definition, not the pack.** See [Reloading](/rp-engine/reloading).

`objects/` holds [3D objects](/rp-engine/objects#sequences) and the
sequences that drive them.

## YAML or TOML

A definition file can be `.yml`, `.yaml` or `.toml`, mixed freely in one
folder. They mean exactly the same thing.

```toml
[ruby]
material = "DIAMOND"
name = "&cRuby"

[chair.place]
facing = "cardinal"
seat = 0.5
```

<Callout type="warning" title="Quote an ID with a / or a . in it">
  Both mean something to TOML, so `weapons/sword` has to be written
  `["weapons/sword"]`. The error message says so when it happens.
</Callout>

## pack.yml

As short as a name:

```yaml
name: My Pack
```

Or with everything it accepts:

```yaml
name: My Pack
description: Swords and statues
version: 1.0.0
bundles: [main]      # which built packs this content goes into
```

`bundles:` is the only one that changes behaviour; see
[Bundles](/rp-engine/bundles). Leave it out and the pack goes into `main`.

## assets/ and overrides/

**`assets/`** becomes `assets/mypack/` in the built pack. It is namespaced, so
nothing in it can collide with another pack or with vanilla.

**`overrides/`** becomes `assets/minecraft/`. It is how you replace vanilla
art: a different dirt texture, a new font, a changed sound.

<Callout type="warning" title="overrides/ is the one place two packs can fight">
  Two packs both replacing `assets/minecraft/textures/block/dirt.png` is a real
  conflict. The namespace that comes later alphabetically wins, and both are
  named in a build warning.
</Callout>

## Blockbench files

`assets/models/` holds Blockbench `.bbmodel` project files or exported Java
`.json` models. The `.bbmodel` is the better choice, because its textures are
inside it. See [Items](/rp-engine/items#3d-items).
