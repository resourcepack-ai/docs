# Other plugins

Every one of these is optional. RP Engine loads and works with none of them
installed, and each is detected at startup — there is nothing to enable.

## PlaceholderAPI

A scoreboard, a chat format, a hologram and a menu plugin can none of them call
an API, and all of them can read a placeholder. Install PlaceholderAPI and
these appear:

| Placeholder | |
|---|---|
| `%rpengine_version%` | The plugin version |
| `%rpengine_items%` | How many items are loaded |
| `%rpengine_models%` · `%rpengine_sounds%` · `%rpengine_screens%` · `%rpengine_huds%` · `%rpengine_entities%` · `%rpengine_recipes%` | The same, per kind |
| `%rpengine_content%` | Everything, counted |
| `%rpengine_namespaces%` | How many packs |
| `%rpengine_emotes%` | How many emotes |
| `%rpengine_bundle%` | The bundle this player is wearing |
| `%rpengine_bundles%` | How many they hold |
| `%rpengine_holds_<bundle>%` | Whether they hold that one |
| `%rpengine_has_<id>%` | Whether this server has that content |
| `%rpengine_holding%` | The content id in their hand, or empty |
| `%rpengine_holding_name%` | The same without the namespace |
| `%rpengine_emoting%` · `%rpengine_can_emote%` | true/false |
| `%rpengine_seated%` | Whether they are sitting on a model |
| `%rpengine_synced%` · `%rpengine_sync_code%` · `%rpengine_sync_owner%` · `%rpengine_sync_size%` | Studio pairing |

They answer questions and never do anything. A placeholder is evaluated
wherever a string is rendered — several times a tick per player on a scoreboard
— so every one of these is a lookup and nothing more.

## WorldGuard

Two region flags:

```
/rg flag spawn rpengine-place deny
/rg flag arena rpengine-use deny
```

`rpengine-place` covers putting a model down and breaking one. `rpengine-use`
covers using a custom item.

Both allow by default, and **anything that goes wrong allows too** — a missing
flag, an exception, a player with bypass. A server locked out of its own
content because a hook broke is a worse outcome than an unguarded region.

<Callout type="note" title="This needed no engine change">
  The whole integration is a listener cancelling
  [events](/rp-engine/api) RP Engine already fired. That is what those events
  are for: a region check baked into placement would have locked every other
  protection plugin out of the same decision.
</Callout>

## MythicMobs

Three mechanics — `rpmodel`, `rpanimate`, `rpunmodel` — so a mob can wear one
of your models and be told to animate from its skill tree. See
[Models on mobs](/rp-engine/mobs#from-mythicmobs).

## Citizens

An NPC keeps the model you bind to it across the despawn and respawn Citizens
does on every chunk unload and restart. See
[Models on mobs](/rp-engine/mobs#from-citizens).

## Geyser

If Geyser-Spigot is on the server, Bedrock players are handed a Bedrock pack
rather than being left out. There is nothing to configure; it is detected and
used.

What it does not do is animate. Bedrock does not translate a Java model rig,
and pretending otherwise would ship Bedrock players a model that stands still
where everybody else sees it move, with nothing to say why.

## What is not here

**Vault, LuckPerms and the rest of the permission plugins** need no
integration: RP Engine checks Bukkit permissions, so whatever provides them
already works. See [Commands and permissions](/rp-engine/commands).

**ItemsAdder and Oraxen** are not integrated with and will not be. Two plugins
both defining custom items on one server is two answers to "what is this item",
and a bridge between them is a promise to keep two id schemes agreeing for
ever.
