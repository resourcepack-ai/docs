# Putting a model on a mob

Any entity on the server can wear one of your models: a MythicMobs boss, a
Citizens NPC, a shopkeeper, a mob another plugin owns. Look at it and run:

```
/rp bind mypack:golem     put the model on the mob you are looking at
/rp unbind                take it off again
```

The entity is not replaced. It keeps its AI, loot, health, hitbox and UUID, and
every plugin that knows about it still has the same entity. Only its vanilla
body is made invisible, and `/rp unbind` brings it back.

To spawn a new mob that comes with a model from your content folder, use
[custom entities](/rp-engine/entities) instead.

## The model is an item ID

Use the same ID a [`place:`](/rp-engine/models) block uses, so one model can
stand in the world and be worn by a mob without being written twice.

If the model animates, the worn copy animates and faces wherever its mob faces.
[Bones that do something](/rp-engine/bones) work here: `h_` heads track what
the mob is fighting, `b_` hitboxes let it be hit where you aimed, `p_` and
`mount` bones are seats, and `tag_` puts its name somewhere sensible.

## Playing animations

A worn model has no clicks to react to, so whatever controls the mob decides
when it animates: a [MythicMobs skill](/rp-engine/mythicmobs) (`rpanimate`),
or [your own plugin](/rp-engine/api) through `Models.animate`.

## What it costs

An animated model is one display entity per moving bone, riding the mob. A
ten-bone boss is eleven entities, so keep detailed rigs for bosses rather than
common mobs.

## Making it stick

`/rp bind` lasts as long as that entity does. A mob that is removed and
respawned by the plugin that owns it comes back without the model. Use the
[Citizens trait](/rp-engine/citizens) or MythicMobs'
[`rpmodel` on `~onSpawn`](/rp-engine/mythicmobs) to put it back on every time.
