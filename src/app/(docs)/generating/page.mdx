# Generating with AI

Generating means describing something in words and having the AI make a first
version of it: a Block texture, a 3D Model, a Sound. You then finish it in the
editor. Each generation costs **AI Credits**, the app's currency, and the price
is shown before you start.

## Generating something

<Steps>
  <Step title="Open Add asset">
    On your pack's page, press **Add asset**.
  </Step>
  <Step title="Pick what you're making">
    Choose a tab along the top (Model, Block, Item and so on), then
    **Generate**.
  </Step>
  <Step title="Fill in the form">
    Write your prompt. Depending on the type you also pick which vanilla block
    or item it replaces, a size for pixel art, or a sound event name.
  </Step>
  <Step title="Press Generate">
    The cost is on the button. Most things take a minute or two, a 3D Model a
    few minutes, and you can leave the page while it works. The new asset
    appears in the pack when it's ready.
  </Step>
</Steps>

If you can't think how to phrase it, press **Write a prompt for me**, say
what you want in a few words, and it fills in the prompt box. That's free.

Making a lot at once, or a whole pack? Press **Chat** instead and describe
it: you get a list of everything to make, with prices, and generate it all
with one button. See [Chat](/chat).

## What each type can start from

**Generate** is the AI. **Blank** opens the editor empty. **Upload** uses a
file you already have.

| Type | Generate | Blank | Upload |
| --- | --- | --- | --- |
| **Model** | ✓ | ✓ | `.json` `.bbmodel` |
| **Block** | ✓ | ✓ | `.png` `.jpg` `.webp` |
| **Item** (2D or 3D) | ✓ | ✓ | `.png` for 2D, `.json` or `.bbmodel` for 3D |
| **Armor** (2D or 3D) | ✓ | ✓ | `.png`, or `.bbmodel` for 3D |
| **GUI** | ✓ | ✓ | `.png` (256×256 sheet) |
| **Dialog** | ✓ | ✓ | ✕ |
| **HUD** | ✓ | ✓ | `.png` sheet |
| **Icon** | ✓ | ✓ | `.png` `.jpg` `.webp` |
| **Rank Tag** (on the Icon tab) | ✓ | ✓ | ✕ |
| **Sound** | ✓ | ✓ | `.ogg` `.mp3` `.wav` |
| **Emote** | ✓ | ✓ | ✕ |
| **Shader** (2D or 3D) | ✓ | ✓ | ✕ |
| **Text Effect** | ✓ | ✓ | ✕ |
| **VFX** | ✓ | ✓ | ✕ |

Pixel art comes in fixed sizes: a generated Block is 16 pixels across, a 2D
Item 16, 32, 64 or 128, and an Icon 8, 16, 32, 64 or 128 pixels tall. Blocks,
2D Items and Icons are each drawn 4 times, and you get the best one (see
below).

An emote **Group** (a set of Emotes a player wears while moving) is made from
Emotes you already have, so it's started blank. Vehicles and Mobs start as a
3D Model: see [Vehicles](/vehicles) and [Mobs](/mobs). Skins are made from
their own page: see [Skins](/skins).

## Giving it a picture to work from

Every type except Sounds, Emotes and Rank Tags can take a **reference image**
beside the prompt, and the AI works from it as well as from your words. A model
built from a reference picks up its shape and colours, which is often the
quickest way to get "like this, but Minecraft". Add one with:

- **Upload**: a picture from your computer (or drop one on the form).
- **From pack**: something already in the pack.
- **From Sketchfab**: paste a Sketchfab model's link and it's used as
  inspiration. Models whose licence doesn't allow commercial use, or whose
  author opted out of AI, can't be used.

## Writing a prompt

Be specific about **material, colour and structure**. Don't describe pixels:
the AI can't count them, and asking it to costs you the parts it's good at.

| Good | Bad | Why |
| --- | --- | --- |
| *weathered copper roof tiles, blue-green patina, strong diagonal grain* | *a nice block, 4px border, dark at the bottom, make it pop* | Material and wear beat pixel instructions |
| *oak market stall, striped red canopy, crate of apples on the counter* | *a detailed medieval shop with lots of decorations* | Named parts give the builder something to build |
| *golden key, ornate bow, three teeth* | *cool key* | The parts you name are the parts you get |
| *heavy iron door slamming, echo in a stone hall* | *scary sound* | Say what makes the noise and where |
| *a red potion bottle, thick dark outline* | *tiny detailed potion icon with sparkles and reflections* | At icon sizes, detail turns to noise |

Things worth naming:

- **The material.** "Oxidised copper" gets further than "green metal".
- **The wear.** New, weathered, cracked, mossy. This is most of what makes a
  texture look like it belongs in Minecraft.
- **The structure.** Planks, tiles, bricks, panels. Give the eye a repeating
  unit.
- **What it sits next to.** "Reads next to deepslate" is a real instruction
  and the AI will use it.

If your pack has a **Style Guide**, the Generate form offers to use it, which
keeps colours and style consistent across everything you make.

## If it isn't quite right

Most generated assets, Skins included, have **Edit with AI** on their page:
describe the change ("same block, fewer colours, calmer surface") and it edits
what's there rather than starting again, so you keep the colours and shape you
liked. On a model it looks at the model's parts first and changes only what you
asked for.
**Regenerate** runs the original prompt again; the old version stays in the
asset's AI history.

A Block, 2D Item or Icon you generate from a description is drawn 4 times, and
Studio picks the best one. On a paid plan the **Versions** card on its page
shows all 4, and clicking another uses it instead, for free. That is often
quicker than another prompt.

<Callout type="warning">
  Edit with AI costs credits like any generation, and on a texture it can
  change pixels you didn't mention. If you've painted something by hand,
  duplicate it first.
</Callout>

Once the shape and colours are right, switch to the editor. Fixing eight
pixels by hand takes fifteen seconds and gets you exactly what you meant;
three more prompts take minutes and give you something slightly different each
time.

## Getting told when it's done

You don't have to watch a model build. Turn on a notification and close the
tab: anything that runs for more than two minutes sends one when it finishes
or fails, with a link back to it.

The settings are on your [account page](https://studio.resourcepack.ai/account),
under **Notifications**. Each channel is separate:

| Channel | Needs |
| --- | --- |
| **Email** | A verified email address on your account |
| **Discord** | Discord connected to your account, and you in [our Discord server](https://resourcepack.ai/discord) |
| **In game** | Your Minecraft account linked; the message arrives on <ServerAddress /> |

<Callout type="note" title="Discord messages need both">
  A Discord bot can only message people it shares a server with. Connect
  Discord and join ours, or no message arrives. If they still don't, check
  that direct messages from server members are allowed in your Discord
  privacy settings.
</Callout>

In-game messages aren't saved for later. If you're offline when it finishes,
you won't get one, so turn on email too if you want a message that waits.
