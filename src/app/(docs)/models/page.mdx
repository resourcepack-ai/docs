# Models

A model is a 3D object made of cubes, each face painted with a texture. It's
the one asset type that changes an object's shape rather than only its
surface: a lamp, a market stall, a statue, a car.

![Models made in Studio: a market stall, a fire engine, a Ferris wheel, a food truck and a vending machine](/images/models.webp)

## Making one

On the pack page, press **Add asset** and pick the **Model** tab. Then:

- **Generate**: describe it. The AI plans the object, builds it cube by
  cube, paints it, and checks its own work. This takes a few minutes and
  costs about 75 credits; you can close the tab while it runs. See
  [Generating with AI](/generating) for writing a good prompt.
- **Blank**: start from a template (a stone cube, a cross like a flower, a flat item, or nothing) and build it yourself.
- **Upload**: bring a Blockbench `.bbmodel` or a vanilla model `.json`. See
  [Importing a model](#importing-a-model).

Generated models look like Minecraft: a few big cubes with the detail painted
onto the faces, rather than hundreds of tiny cubes. A barrel is one cube with a
rim painted on it.

Once you have a model, **Edit with AI** on its page changes it from a sentence
("make the roof red", "add a chimney"), and **Animate with AI** in the editor
writes animations for it. Editing with AI repaints the model in the same
generated style, even if you uploaded it.

<Callout type="tip" title="Generation is a starting position">
  The loop that gives good results: generate, look at it in game, fix the two
  things that are wrong, look again.
</Callout>

## The editor

A Blockbench-style editor with five modes, chosen along the top:

| Mode | For |
| --- | --- |
| **Edit** | Building the shape: add, move, resize and rotate cubes, and group them into bones |
| **Paint** | Painting straight onto the model in 3D |
| **Display** | How it looks in a hand, in the inventory, on the ground, in an item frame, on a head |
| **Render** | Capturing a PNG of the model on a backdrop |
| **Animate** | Keyframes and when they play; see [Animations](/animations) |

## Edit mode

A model is a list of **cubes** (Minecraft calls them elements). Each cube is a
box with six faces, and each face shows part of a texture.

Positions are in pixels, 16 to a block. A cube can sit anywhere from `-16` to
`32` on each axis, with the block itself at `0` to `16`, so a model can
overhang its block by a full block on every side. Keep the bulk of it near the
middle so it sits well when placed.

Cubes can be turned to any angle, on more than one axis. Minecraft's own
format only allows a few angles on one axis, so a model with other turns needs
RP Engine to show them exactly; a plain exported pack shows the nearest angle
it can.

### Hotkeys

Defaults, all changeable in the editor's settings:

| Action | Key |
| --- | --- |
| Move tool | `G` |
| Resize tool | `S` |
| Rotate tool | `R` |
| Frame selection | `F` |
| Hide / show cube | `H` |
| Duplicate cube | `Ctrl+D` |
| Select all | `Ctrl+A` |
| Copy / paste | `Ctrl+C` / `Ctrl+V` |
| Delete cube | `Delete` |
| Deselect | `Esc` |
| Undo / redo | `Ctrl+Z` / `Ctrl+Y` |

Copied cubes paste into any model, in another tab or another pack too. Any
textures they use come with them.

The tool rail also has a **Select** tool, for picking without a gizmo, and a
**Pivot** tool, which moves the selected cube's pivot point without moving the
cube. Use it when a cube turns around the wrong spot.

### Bones

Select several cubes and group them into a **bone**: a named group with its
own pivot point. Bones are what you animate. Turning a bone turns everything
in it around one point, which is how a door swings or a wing flaps.

Select a cube in a bone and the right panel shows the **Bone** card, with the
bone's own pivot point and **Select members**, which selects every cube in the
bone. The Move tool then moves the whole bone, its pivot going along. In Edit
mode the Rotate tool turns each selected cube around its own pivot. To turn a
bone as one piece, use Animate.

A generated model arrives already grouped, with named parts and pivots at the
joints (a front wheel pivots on its axle), so it's ready to animate.

Bones are saved in the same `groups` field Blockbench uses. Vanilla Minecraft
ignores it, so grouping never breaks an exported pack.

### Copying a texture to another model

To use one model's texture on another, select it and press `Ctrl+C`: in Paint
mode, the texture you're painting; in Edit mode, pick a face in the inspector
first (with only a cube selected, `Ctrl+C` copies the cube). **Copy texture**
in Paint mode's right-click menu and the copy button beside a face's texture do
the same. Then, in the other model (any tab, any pack), select cubes or faces
and press `Ctrl+V`. With cubes selected, it goes on every face; with faces
picked, only on those. A texture from another pack is copied into this one
first.

### UVs

Which part of a texture lands on which face is normally handled for you. The
UV panel in Edit mode is there for when you need exact control.

## Paint mode

Paint straight onto the model in 3D. For anything fiddlier than a quick
touch-up, open the texture in the full [pixel editor](/blocks) from here; it
comes back when you're done.

## Display mode

Minecraft draws a held or displayed model differently in each place, and each
place has its own rotation, position and scale:

- **First person** and **third person**, in each hand
- **On a head**
- **On the ground**, as a dropped item
- **Item frame**
- **Shelf**
- **GUI**, the inventory icon

Slots you leave alone use the vanilla defaults, so only change the ones that
look wrong. The preview has a player (Steve, Alex or your own skin) so you can
judge a held model against a body.

<Callout type="tip">
  Take care over the GUI slot. The inventory icon is how players find your
  model at all.
</Callout>

**Model scale**, also in the editor, resizes the model itself, so every copy
is that size in the exported pack too.

## Render mode

The same viewport set up for screenshots. Pick a backdrop (Transparent,
solid colours including a green screen, gradients, or a Minecraft sky and
grass), frame or spin the model, and capture a PNG. A transparent backdrop
gives a PNG with a real transparent background, ready for a Discord post or a
store listing.

## Importing a model

Two formats upload:

- **`.bbmodel`** (Blockbench) keeps its cube names, its groups (as bones), its
  animations, its textures and its rotations, so a rigged Blockbench model
  arrives ready to animate.
- **`.json`** (a vanilla block model) comes in as geometry. A vanilla *item*
  model that only names a texture, like the wheat seeds, has no cubes in it and
  is refused with "Model has no valid geometry": make that one an
  [Item](/items) instead.

A model too big for Minecraft's model box is scaled down to fit.

<Callout type="warning">
  Cubes only. Minecraft's model format has no meshes, so mesh geometry in a
  Blockbench file doesn't come across.
</Callout>

## Seeing it in game

A resource pack can't add new items or blocks to Minecraft. It can only change
how existing ones look. So every model rides on a piece of vanilla **paper**:
the pack tells the game to draw that paper as your model. The Add asset sheet
calls this the **Display Entity** carrier.

Placing the model in the world needs [RP Engine](/testing/plugin) on the
server. The test server has it.

1. **Sync** the pack to yourself.
2. On the model's page, under **Get in-game**, press **Give in-game** (or copy
   the give command).
3. **Right-click a block** to place it. It appears on the block you clicked,
   facing the way you were looking.
4. **Punch it** to pick it back up. A model with an "On left click" animation
   can't be punched up; see [Animations](/animations).

A placed model is a display entity, not a block. It doesn't fill a block
space or stop water, and it stays put across server restarts. Block
protection plugins don't necessarily cover it, so check that on a public
server.

### Choosing what it gives

The **Get in-game** card has a few options that ride on the item, so you can
give different copies of one model different settings:

- **Size**: from ⅛ to 8 times. The model grows from its base, so a big one
  stands on the block rather than sinking into it. The dropped item remembers
  its size.
- **Plays**: shown when the model has two or more triggered animations, to
  pick which one this copy uses. See [Animations](/animations#triggers).

### Vehicles driving into it

Under the card, **Placed behaviour** has one checkbox: **Make this model
collidable with vehicles**. It's on by default. When on, vehicles stop at a
placed copy of the model, tested against its actual cubes: a car can drive
between the legs of a table or under an archway, and a long fence stops it
along its whole length. A rotated slab works as a ramp, stairs are climbed a
step at a time, and anything low enough to be a kerb is driven over.

Turn it off for flat pieces a vehicle should ignore, like a rug, a manhole
cover or a road marking. It doesn't affect players, who walk through placed
models unless the server sets otherwise. The change reaches the server on the
next Sync. It isn't shown for a model that's been converted into a
[vehicle](/vehicles).

## Exporting

A model is exported as a JSON file in Minecraft's block-model format, with
its textures beside it. An item definition for paper points at it, so paper
with the right item data draws as your model. The give command on the model's
page produces that item.

<Callout type="warning" title="Animations need RP Engine">
  Keyframes and bones are saved in fields vanilla ignores. The pack is still
  valid, but the model stands still unless RP Engine is playing it. See
  [Animations](/animations).
</Callout>

## On Bedrock

Models convert to Bedrock. The `.mcpack` carries each model as a Bedrock
entity, with your animations as native Bedrock animations, and cube rotations
come across exactly.

Something still has to put that entity in the world. On a server that's
[RP Engine](/rp-engine/bedrock), which draws placed models for Bedrock players
near them. Without it, a model is its item: Bedrock players hold it with the
model's icon, given by the same command, if the server has the
[Geyser export](/bedrock#without-rp-engine). A `.mcpack` in a Bedrock world on
its own has the models defined but nothing to place them.
