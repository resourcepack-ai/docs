# Shaders

A Shader is part of your resource pack that the player's graphics card draws,
instead of a flat picture. Studio makes two kinds:

![Shader objects made in Studio: a black hole, a ringed planet, a galaxy in a globe and a fireball](/images/shaders.webp "plain")

- **2D: a piece of HUD you design.** A health bar in the corner, a nameplate at
  the top of the screen, a badge beside the hotbar. It can show live values
  such as the player's health. Needs [RP Engine](/rp-engine) on the server.
- **3D: an object in the world.** A black hole, a soap bubble, a ball of fire:
  things a block model can't be. Works with a plain `/summon` command, no
  plugin needed. See [3D objects](#3d-objects).

Studio calls each one a **shader object**. Two related kinds have their own
pages: [Text Effects](/text-effects) make text wave, burn or shine, and
[VFX](/vfx) are spell effects in the world.

## Making a 2D shader object

1. Open a pack, press **Add asset**, pick the **Shader** tab and leave the
   switch on **2D**.
2. Press **Blank** to build it yourself, or **Generate** and describe it (10
   credits), for example "health, hunger and level in the bottom left". A
   generated one is made of ordinary pieces you can keep editing.
3. Draw and place it in the editor (below).
4. Press **Sync** and run the `/rp sync <code>` it shows in game. Sync sends
   the pack straight to you on your server and puts the object on your screen.
5. Decide when players see it: see [Showing it in game](#showing-it-in-game).

<Callout type="warning" title="A 2D shader object needs RP Engine">
  The art is in your resource pack, but the server has to put it on each
  player's screen and fill in the live values. That is [RP Engine](/rp-engine).
  Without it the pack loads and nothing appears.
</Callout>

## The editor

It is laid out like the GUI editor: tools down the left, the **Elements** list
beside them, the canvas in the middle, and settings on the right.

### What you can put in it

Everything sits in the Elements list under **Canvas**. Whatever is higher in
the list is drawn on top. Use the arrows on a row to move it.

- **Components**: labels, player heads, progress bars and pictures. The first
  three can change while people play.
- **Paint**: freehand pixels on layers.
- **Shapes**: rectangles, circles, triangles and polygons, drawn as smooth
  maths so they stay crisp at any GUI scale.

Add components and shapes with the **+** beside Elements.

### Components

| Component | What it is |
| --- | --- |
| **Label** | A line of Minecraft text. It can include [live values](#live-values) like `{player}` or `{health}` |
| **Player head** | The face of the player looking at it. In the editor, and in an exported or distributed pack, it is Steve. A pack sent with **Sync** shows the real faces of the players it was sent to |
| **Progress bar** | Fills from a live value, solid or in segments. It can change colour as the value passes thresholds you set, and **Glow** gives it a soft halo (leave room round it: the glow stops at the canvas edge) |
| **Picture** | An image you upload or have drawn. Pictures are shared across the pack, so one upload can be used by any number of objects |

Drag components to move them, or nudge the selected one with the arrow keys
(hold Shift for 10 pixels).

### Paint

Pick a brush on the left (pencil, eraser, fill, colour picker, line,
rectangle, ellipse or pixel text) and draw. It draws on the paint layer
selected in the list, and picking a brush makes one if there are none. Layers
can be hidden, renamed (double-click), duplicated, merged down, cleared or
deleted. With the **Select** tool, dragging on paint moves that layer.

Paint is pixel art, one pixel per GUI pixel, so it looks blocky on a large
canvas where shapes stay smooth. Pixel text is ordinary pixels: for text that
changes in game, use a **Label**.

### Shapes

**Rectangle**, **Circle**, **Triangle** and **Polygon**. A rectangle's
**Corners** setting rounds it, and a circle's **Outline** setting turns it into
a ring. Drag the handles to resize.

Shapes combine with the shapes directly below them in the list: **Add** draws
on top, **Cut** removes itself from them, **Keep overlap** keeps only where
both exist, and **Blend** joins them with a smooth curve.

### The canvas: size and place on screen

Select **Canvas** in the list.

- **Size**: up to 1024 by 1024, in steps of 8. Paint and shapes are clipped to
  the canvas; labels, heads and bars can sit outside it.
- **Where on screen**: snap it to a corner, an edge or the middle, then nudge it
  by pixels. A corner stays a corner at every window size and GUI scale.
  **Reposition on screen** lets you drag it around a full game screen.
- **Action bar or boss bar**: which of the two the object travels through. The
  action bar fades, so RP Engine keeps re-sending it. The boss bar shows and
  hides instantly.

**Preview**, in the header, shows the object on a game screen at its real size.

### Covering the whole screen

For a tint, a vignette, a frame round the edges or a HUD with a piece in every
corner, tick **Fill the whole screen** on the Canvas row. The object then
covers every player's screen at any size.

Each element is then **pinned** to one of nine points of the screen (a corner,
the middle of an edge, or the centre), chosen in its **On the screen**
settings. Its X and Y are measured from that point, so a bar pinned
bottom-right at -4, -4 always sits four pixels in from that corner.

- **Labels** line up on their point: pinned right, the words end there and grow
  leftward.
- **Shapes** can **Stretch with the screen**. They are sized on a 640 by 360
  screen and scale with the real one.
- **Paint** keeps its own box, set under **Paint area**.

The buttons above the canvas preview four common screen sizes. Unticking the
box turns it back into a normal canvas.

## Live values

A label or progress bar can show a value that is different for each player.
Write it in curly braces, like `{health}`.

| Placeholder | What it is |
|---|---|
| `{player}` | Their name |
| `{displayname}` | Their name with any prefix a plugin gave it |
| `{health}`, `{health_max}`, `{health_percent}` | Health |
| `{food}` | Hunger, out of 20 |
| `{level}`, `{xp}` | Experience level, and progress to the next as a percentage |
| `{xp_points}`, `{xp_needed}` | Experience points into this level, and how many the level takes |
| `{air}` | Seconds of breath left underwater |
| `{ping}` | Latency in milliseconds |
| `{world}`, `{x}`, `{y}`, `{z}`, `{direction}` | Where they are |
| `{time}`, `{day}` | The world's clock, and how many days it has run |
| `{gamemode}` | Survival, Creative and so on |
| `{online}`, `{max_online}` | Players online, and the server's cap |
| `{uuid}` | Their account UUID |

A progress bar fills from a value out of a maximum: `{health}` out of
`{health_max}`, `{food}` out of 20, `{xp}` out of 100, `{air}` out of 15.

PlaceholderAPI values work too, and **your own plugin can publish any value**
under any name with `overlays().set(player, "stamina", "40")`. See [the RP
Engine API](/rp-engine/api#hud-overlays).

## Changing it from code

Every label, head, picture and progress bar has a **From code** section at the
bottom of its settings. Each field takes a live value, the same way a
`{name}` does.

| Field | What it does |
| --- | --- |
| **Show when** | Hides the piece while a condition is false, such as `{rank} == "vip"`, `{mana} > 10` or `perm:hud.extra`, joined with `&&` and `\|\|`. The same language as a dialog's Show when |
| **Add a colour** / **Picked by** | Named colours (such as `poisoned`, `frozen`) and the value that picks one. Any other value draws the normal colour. On a bar, a named colour wins over the thresholds |
| **Length from** | A progress bar's length in pixels |
| **Thresholds from** | Moves a colour threshold, as a percentage |

```java
engine.overlays().set(player, "status", "poisoned");
engine.overlays().set(player, "mana_len", "120");
```

Shapes and paint are fixed in the pack, so their size and colour can't change
in game, and code can only pick colours you set in Studio.

## Showing it in game

An object does nothing until something shows it. There are three ways:

- **A rule**, set on the Canvas: **Always** (the whole time they're online),
  **On join** (once, as they join), **While crouching**, or **While holding**
  an item. Any rule can also require a permission.
- **A command**: `/rp shader studio:<id> [player]` shows it, `/rp shader clear`
  takes them all off, and `/rp shaders` lists every one on the server. These
  need the `rpengine.shader` permissions (op by default).
- **Your plugin**: `overlays().show(player, "studio:<id>")` and
  `overlays().hide(...)`. See [the RP Engine API](/rp-engine/api#hud-overlays).

**Finding the id.** Open the shader: the **In game** section at the top of the
Canvas settings shows the full command and the `overlays().show` line, with copy
buttons. The copy button on the shader's card on the pack page copies the
command too. The id is made from the name the object was **created** with, and
renaming it later doesn't change the id, so don't guess it from the current
name.

To get it to everyone on your server, not just you, serve the pack with
[Distribution](/distribution) (players get it as they join), or export the pack
as a `.zip` and drop it into RP Engine's `content/` folder ([Adding a resource
pack](/rp-engine/resource-packs#a-pack-from-resourcepack-ai-studio)). Both need
RP Engine 0.2.38 or newer.

## Limits

- **32 pieces per object.** A label, player head or picture takes one. A
  progress bar takes two, plus one per colour threshold. Each named colour
  takes one. Paint takes one per 256-pixel tile of drawing. The status bar at
  the bottom of the editor counts them, and anything past 32 isn't drawn.
- **A full-screen object draws over the hotbar and crosshair** and under chat
  and titles. Keep it to a handful of shapes: each is worked out for every
  pixel of the screen, every frame.
- **Only players with your pack see it.** RP Engine doesn't send an object to
  anyone who lacks the pack it came from.
- **Minecraft 1.19.4 to 26.3.**
- **Not in the ItemsAdder export.**

If something looks wrong, it helps to know how it works: the server can only
send a line of text to the action bar or boss bar. Your object ships as special
characters in the pack's font, and a text shader in the pack recognises them by
their exact colour and moves them where you placed them. Another plugin's
resource pack that also replaces the text shader can stop it drawing.

## 3D objects

A 3D object sits in the world and looks like nothing a cube model can make: a
swirling portal, a planet, a glowing orb, a black hole. It is smooth and round
from every side and can move.

### Making one

Press **Add asset**, pick the **Shader** tab, switch to **3D** and describe it,
for example "a slowly spinning plasma orb with a purple core and crackling
white arcs". It costs 30 credits and takes a few minutes. There is nothing to
draw by hand, so **Blank** isn't offered.

Glow, smoke, energy, glass and motion work best. One centred object works
better than a whole scene.

### Its page

There is no editor. The page shows the object running live:

- **Drag to orbit, scroll to zoom.** The floor squares are blocks, so you can
  judge its size.
- **Edit with AI**: describe a change ("make the glow bluer", "spin it
  slower"). The object keeps its old look until the change is done, and if the
  change fails.
- The line under the name says how hard it is on a player's graphics card:
  **light**, **moderate** or **heavy** to draw. Several heavy ones on screen at
  once can cost frame rate on a slow machine.

### Putting it in the world

Under **Get in-game**, set the **Size** (a quarter of a block to 64 blocks
across), then either:

- **Copy the `/summon` command** and run it where you stand, with the pack
  applied. **No plugin is needed**: it works on any server or in single
  player. The object appears just above you and always faces the camera.
  Players can't hit or break it; remove it with `/kill`.
- **Place in game** puts it in front of you on the server your pack is
  [synced](/testing/plugin) to. Sync first.

Blocks in front of it hide it, like any other object.

### Moving and changing it from a server

With [RP Engine](/rp-engine) 0.2.10 or newer, a server can switch a placed
object between the looks its code defines (a portal opening and closing, say)
and move, turn and resize it smoothly. Sequences of these steps go in RP
Engine's `objects/` content folder.

| Command | Does |
| --- | --- |
| `/rp objects` | Lists the objects the server has |
| `/rp object spawn <id> [size] [x y z]` | Places one in front of you, or at those coordinates |
| `/rp object state <name>`, `replay <name>` | Puts the nearest object into a state, or restarts it |
| `/rp object play <sequence>`, `stop` | Runs or stops a sequence on the nearest object |
| `/rp object move`, `turn`, `size`, `seed` | Moves, turns or resizes the nearest object |
| `/rp object remove [all]` | Takes it away |

Each verb has its own permission, `rpengine.object.<verb>`, all granted by
`rpengine.object`, and every verb works from a command block. This needs a
pack set to 26.2 or newer and a server on Minecraft 1.21.4 or newer. See
[3D objects](/rp-engine/objects) for sequences and the full reference.

### Bubbles, glass and black holes

Some objects bend the world behind them: a bubble refracts it, and a black hole
pulls it into a curve. That needs a **26.2** pack and **Improved Transparency**
turned on in the player's Video Settings; without it, a bubble shows as a faint
outline. With both, blocks that cut through any 3D object get a bright edge.
On 26.3 neither effect is drawn.

### 3D limits

- Apart from the bending above, it can't distort the world behind it, and it
  casts no shadow.
- Fog doesn't reach it, so a distant object stays as bright as a near one.
- A summoned object always faces the camera. Only one placed by RP Engine can
  be turned.
- Players without your pack don't see it.
- Not in the Bedrock or ItemsAdder exports.
