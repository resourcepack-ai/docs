# Quickstart

This page takes you round the whole loop once: make a pack, generate a new
stone texture into it, and walk up to it in Minecraft. It takes about five
minutes.

<Callout type="note" title="You'll need">
  A free ResourcePack AI account, and Minecraft: **Java or Bedrock**. You don't
  need to install anything. Generating uses **AI Credits**, the app's
  currency: a free account gets 50 every month, and a Block costs 10.
</Callout>

## Make something

<Steps>
  <Step title="Create a pack">
    Open [studio.resourcepack.ai](https://studio.resourcepack.ai) and press
    **New pack**. Give it a name; the description and icon are optional. A
    pack holds everything you make, and it's what you test and export.
  </Step>
  <Step title="Press Add asset">
    Each thing in a pack is an **asset**. The sheet that opens has a row of tabs across the top for **what** you're
    making: Model, Block, Item, Armor, GUI, Dialog, HUD, Icon, Sound, Emote,
    Shader, Text Effect and VFX. Under them you choose **how** to start:

    | Option | What it does |
    | --- | --- |
    | **Generate** | You describe it and the AI makes it |
    | **Blank** | Opens the editor with nothing in it |
    | **Upload** | Uses files you already have |

    Pick the **Block** tab and **Generate**.
  </Step>
  <Step title="Describe what you want">
    Choose the vanilla block to replace (say, **Stone**), then describe the
    new look in a sentence. Every stone block in the game will wear it. Talk about the material and its
    wear, not about pixels:

    > weathered copper roof tiles, blue-green patina, strong diagonal grain

    The cost is shown next to the **Generate** button before you press it. A
    Block takes a minute or two. A 3D Model takes a few minutes, and you can
    leave the tab while it works. See
    [Generating with AI](/generating) for every type and what it costs.
  </Step>
  <Step title="Edit it">
    What comes back is a starting point, not the finished thing. Click it to
    open its editor and fix what isn't right. Blocks, Items and Icons open in
    the [pixel editor](/blocks), and 3D Models in the [model editor](/models).
  </Step>
</Steps>

## See it in Minecraft

The quickest way is our test server. It already runs everything a pack needs.

<Steps>
  <Step title="Join the test server">
    In Minecraft, add the server <ServerAddress /> and join, from Java or
    Bedrock. Go through the portal in the lobby for a private world of your
    own, which is kept between visits.
  </Step>
  <Step title="Link your account (once)">
    In Studio, open your account page. Under **Minecraft account**, press
    **Get link code**, then type the command it shows in game:

    ```
    /permlink 48213097
    ```

    You only do this once. It tells Studio which Minecraft player is you, so
    it knows where to send your pack.
  </Step>
  <Step title="Press Sync">
    Back in Studio, press **Sync** at the top of the pack page. Sync sends the
    pack to your game, to you alone: other players don't see it. On Java the
    new stone appears where you're standing in a few seconds. On Bedrock you're disconnected
    and reconnected for a few seconds, because Bedrock only accepts a pack
    while joining.
  </Step>
  <Step title="Go round again">
    Change something in Studio, press Sync, look again. Good packs come from
    going round this loop a lot, not from getting it right first time.
  </Step>
</Steps>

<Callout type="tip" title="Your own server">
  To test on your own Paper or Spigot server instead, install our plugin,
  [RP Engine](/testing/plugin). Sync works there the same way.
</Callout>

## When it's finished: export it

You never need a file to test. When the pack is done, export it as a Java
`.zip` or a Bedrock `.mcpack` from the pack page. To use the `.zip` in your
own game, put it in your `resourcepacks` folder:

```bash
# Windows
%APPDATA%\.minecraft\resourcepacks

# macOS
~/Library/Application Support/minecraft/resourcepacks

# Linux
~/.minecraft/resourcepacks
```

Then turn it on under **Options → Resource Packs**. The exported pack doesn't
depend on us and keeps working if you never open Studio again. The exceptions
are things vanilla Minecraft can't do on its own, such as animated models,
Vehicles and Emotes, which need RP Engine on the server. See
[Exporting a pack](/exporting).
