# Quickstart

One full loop: make a pack, generate something into it, look at it in
Minecraft. Everything else in these docs is a variation on that loop.

<Callout type="note" title="You'll need">
  A ResourcePack AI account, and Minecraft — **Java or Bedrock**, both work.
  Nothing to install for either.
</Callout>

## Make something

<Steps>
  <Step title="Create a pack">
    Open [studio.resourcepack.ai](https://studio.resourcepack.ai) and create a
    pack. A pack is the container for everything else — textures, models,
    icons — and it's the unit you export and test. Studio starts you with a
    name and banner; use the dice to randomize both, or upload your own image.
  </Step>
  <Step title="Describe what you want">
    Say it in a sentence and generate it. Be specific about material and wear,
    not about pixels:

    > weathered copper roof tiles, blue-green patina, strong diagonal grain

    Seconds later you have a texture — or, from the same box, a model built out
    of cubes and real vanilla materials, or an icon. You pick the
    resolution on the way in: 16, 32, 64 or a custom size.

    See [Generating with AI](/generating) for what makes a prompt land.

    <Callout type="note">
      You can also upload art you already have, or start from a blank grid, if
      you'd rather draw the whole thing yourself.
    </Callout>
  </Step>
  <Step title="Edit it">
    Nothing generated is final, and that's the point: generation is a faster
    starting position than an empty grid, not a finished product.

    Textures open in the [pixel editor](/editors/textures); models open in the
    [model editor](/editors/models), which has separate modes for shaping
    geometry, painting it, positioning it in hand, and animating it.
  </Step>
</Steps>

## See it in Minecraft

The fastest route is our test server — no plugin, no setup.

<Steps>
  <Step title="Join play.resourcepack.ai">
    ```
    play.resourcepack.ai
    ```

    Java or Bedrock, same address. You'll land in the lobby. Take the portal
    for a private world of your own, which is kept between visits, or use the
    shared plot up front for a quick look.
  </Step>
  <Step title="Link your account, once ever">
    On your account page, under **Minecraft account**, press **Get link
    code**, then run it in game:

    ```
    /permlink 48213097
    ```

    That's the last code you'll type. From here on, studio knows who you are
    on the server.
  </Step>
  <Step title="Push">
    Hit **Sync** on the pack and it goes straight to your client. Nothing is
    downloaded, zipped or uploaded by you. On Java the pack swaps in where
    you're standing; on Bedrock you're bounced out and back in for a few
    seconds, because Bedrock only takes a pack while joining.
  </Step>
  <Step title="Iterate">
    Change something in studio, push again, look again. Most of the work is in
    how many times you go round this loop, not in getting it right first time.
  </Step>
</Steps>

<Callout type="tip" title="Own server instead?">
  Any Paper or Spigot server can run our plugin and take pushes the same way.
  There it's a per-pack `/link` code rather than a one-off permalink — see
  [Your own server](/testing/your-server).
</Callout>

## Export it (optional)

You never have to do this to test — the loop above never touches a file. But a
finished pack is an ordinary Minecraft resource pack, and you can take it with
you: export Java `.zip` or Bedrock `.mcpack`. The `.zip` goes in your
`resourcepacks` folder:

```bash
# Windows
%APPDATA%\.minecraft\resourcepacks

# macOS
~/Library/Application Support/minecraft/resourcepacks

# Linux
~/.minecraft/resourcepacks
```

There's no runtime dependency on us in the exported file — it keeps working
if you never open studio again. The exception is animated models, which need
our plugin to play back; see [Animations](/editors/animations).
