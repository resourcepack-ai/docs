# Quickstart

This page takes you round the whole loop once: make a pack, generate a block
into it, and see it in Minecraft.

<Callout type="note" title="You'll need">
  A free ResourcePack AI account, and Minecraft: **Java or Bedrock**. You don't
  need to install anything. The free plan comes with 50 AI credits a month,
  and a block texture costs 10.
</Callout>

## Make something

<Steps>
  <Step title="Create a pack">
    Open [studio.resourcepack.ai](https://studio.resourcepack.ai) and create a
    pack. Give it a name, and optionally a description and an icon. A pack
    holds everything you make, and it's what you test and export.
  </Step>
  <Step title="Press Add asset">
    The sheet that opens has a row of tabs across the top for **what** you're
    making: Model, Block, Item, Armor, GUI, Dialog, HUD, Icon, Sound, Emote
    and Shader. Under them you choose **how** to start:

    | Option | What it does |
    | --- | --- |
    | **Generate** | You describe it and the AI makes it |
    | **Blank** | Opens the editor with nothing in it |
    | **Upload** | Uses files you already have |

    Pick the **Block** tab and **Generate**.
  </Step>
  <Step title="Describe what you want">
    Choose the vanilla block to replace (stone, oak planks, anything), then
    describe the new look in a sentence. Talk about the material and its
    wear, not about pixels:

    > weathered copper roof tiles, blue-green patina, strong diagonal grain

    The cost is shown next to the **Generate** button before you press it. A
    block takes a minute or two. Bigger things take longer: a 3D model takes
    a few minutes, and you can leave the tab while it works. See
    [Generating with AI](/generating) for every type and what it costs.
  </Step>
  <Step title="Edit it">
    What comes back is a starting point, not the finished thing. Click it to
    open its editor and fix what isn't right. Blocks, items and icons open in
    the [pixel editor](/blocks), and models in the [model editor](/models).
  </Step>
</Steps>

## See it in Minecraft

The quickest way is our test server. It already runs everything a pack needs.

<Steps>
  <Step title="Join the test server">
    Connect to <ServerAddress /> from Java or Bedrock. Go through the portal
    for a private world of your own, which is kept between visits.
  </Step>
  <Step title="Link your account (once)">
    In Studio, open your account page. Under **Minecraft account**, press
    **Get link code**, then type the command it shows in game:

    ```
    /permlink 48213097
    ```

    You only do this once. After that, Studio knows which player is you.
  </Step>
  <Step title="Press Sync">
    Press **Sync** on the pack and it goes straight to your game. On Java the
    new textures appear where you're standing. On Bedrock you're disconnected
    and reconnected for a few seconds, because Bedrock only accepts a pack
    while joining.
  </Step>
  <Step title="Go round again">
    Change something in Studio, press Sync, look again. Good packs come from
    going round this loop a lot, not from getting it right first time.
  </Step>
</Steps>

<Callout type="tip" title="Your own server">
  To test on your own Paper or Spigot server instead, install
  [RP Engine](/testing/plugin). It takes pushes from Studio the same way.
</Callout>

## Export it (optional)

You never need a file to test. When the pack is done, export it as a Java
`.zip` or a Bedrock `.mcpack` from the pack page. To use the `.zip` in your
own game, put it in your `resourcepacks` folder:

```bash
# Windows
%APPDATA%\.minecraft\resourcepacks

# macOS
~/Library/Application Support/minecraft/resourcepacks

# Linux
~/.minecraft/resourcepacks
```

Then turn it on under **Options → Resource Packs**. The exported pack doesn't
depend on us and keeps working if you never open Studio again. The exceptions
are the things vanilla Minecraft can't do on its own, such as animated models,
vehicles and emotes, which need RP Engine on the server. See
[Exporting a pack](/exporting).
