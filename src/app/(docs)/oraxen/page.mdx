# Oraxen export

The Oraxen export is content for a server already running
[Oraxen](https://docs.oraxen.com/). It gives Oraxen item and glyph YAML and the
resource pack assets it needs to generate and send one combined pack to
players.

## Install it

1. In Export, choose **Plugin Support → Oraxen**.
2. Unzip the download directly into your server's `plugins/` folder.
3. Run `/oraxen reload all`, then rejoin or run `/oraxen pack send <player>`.

The download has this shape:

```
plugins/
  Oraxen/
    items/<your-pack>/items.yml
    glyphs/<your-pack>/glyphs.yml
    pack/uploads/<your-pack>/
  datapacks/<your-pack>_dialogs/      ← only if the pack has dialogs
```

Oraxen merges folders in `pack/uploads` while it generates its resource pack.
Give an exported item with `/oraxen give <player> <item-id>`. The ids are the
keys in `items.yml`, and the download's `README.txt` lists them along with
everything else it contains.

## What comes across

| In your pack | In Oraxen |
| --- | --- |
| 3D model | furniture (display entity): hold it, or right-click a block to place it. Its hitbox is measured from the model |
| Vehicle | furniture with the vehicle's seats, so players can sit in it |
| Custom block | an Oraxen `block` (type `FULL`, note block), mined and dropped like any Oraxen block |
| Custom 2D item, 3D item | an Oraxen item, keeping its name and the vanilla item a variant is built on |
| Vanilla item in 3D | the vanilla item itself, reskinned for everyone |
| Icon | an Oraxen glyph: `<glyph:<pack>_<icon>>` in Oraxen text, and `:icon:` in chat |
| GUI overlay | an Oraxen glyph, plus a ready-made inventory title (see below) |
| Pause-menu buttons | the redrawn buttons, as in the Java pack |
| Sounds | merged into the pack's sounds, under the event names you gave them |
| Block, item, armour and GUI reskins | vanilla-file replacements in Oraxen's pack |
| Dialog | a datapack folder (see below) |

The YAML uses Oraxen's current lowercase sections (`pack:`, `mechanics:`), so
Oraxen loads it as written instead of migrating it. Oraxen supplies the item
model wiring and the note-block state. Change an item's `material` in
`items.yml` if it should keep vanilla behaviour instead of the safe default
`PAPER`.

### GUI titles

Oraxen draws GUIs with glyphs in an inventory title. `README.txt` gives each
GUI's title in Oraxen's tags, for example
`<shift:-48><glyph:my_pack_gui_shop>`: paste it as that menu's title in your
menu plugin.

### Characters are pinned

Every glyph keeps the character ResourcePack AI gave it, written as `char:` in
`glyphs.yml`, because the pause-menu text and GUI titles already use those
characters. Oraxen assigns its own glyphs from U+A410 upward, so they do not
meet.

### Dialogs

Oraxen does not install vanilla dialogs, so a pack with dialogs also gets
`datapacks/<your-pack>_dialogs/`. Move that folder into your world's
`datapacks/` folder and restart. Open a dialog with
`/dialog show <player> studio:<id>`. This needs Minecraft 1.21.6 or newer.

## Limits

Some content is drawn by [RP Engine](/rp-engine) while the game runs, and no
Oraxen configuration can express it. The README names each one the pack has:

- **Shader objects**: RP Engine sends the text they draw on.
- **3D armour**: RP Engine poses the pieces on the wearer.
- **Animation**: models place as still furniture.
- **Driving**: vehicles place as furniture you can sit in, not drive.
- **Dialog switches and sliders bound to player settings**: they open, but
  remembering a choice needs RP Engine.

<Callout type="warning" title="Vanilla replacements are server-wide">
  Reskinned blocks, items and vanilla GUI screens apply to everyone sent
  Oraxen's pack. Delete the corresponding asset from `pack/uploads` if you do
  not want that replacement.
</Callout>
