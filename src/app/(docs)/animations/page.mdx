# Animations

You can make a model move: a door that swings open, a fan that spins, a chest
lid that opens when someone walks up. You keyframe it in the model editor's
**Animate** mode, or have the AI do it, and choose what makes it play.

Vanilla Minecraft can't animate a model, so playback in game is done by
[RP Engine](/testing/plugin), our server plugin. Our test server runs it.

<Callout type="warning" title="On Java, animations need RP Engine">
  A pack with an animated model is still a valid resource pack, but the model
  stands still anywhere RP Engine isn't running. Bedrock is different: its
  pack carries the animations natively. See [On Bedrock](#on-bedrock).
</Callout>

## Animating in the editor

<Steps>
  <Step title="Group what moves into bones">
    Animate mode moves **cubes** and **bones** (named groups of cubes that
    share a pivot point, made in Edit mode). A hinge, a wheel or a wing should
    each be a bone, so it turns around one point. Generated models arrive
    already grouped, with pivots at the joints.
  </Step>
  <Step title="Add keyframes">
    Create an animation and give it a name and a length in seconds. Pick a
    cube or bone, move the playhead, and change its rotation, position or
    scale: a keyframe is set at that time. Keyframes past the end are dropped
    if you shorten the animation.
  </Step>
  <Step title="Choose how it moves between keyframes">
    Each keyframe has an interpolation:

    - **Linear**: a straight line between values. The default.
    - **Smooth**: a curve through the neighbouring keyframes. Good for
      anything organic.
    - **Step**: hold the value, then jump. Good for mechanical snaps.

    Before the first keyframe and after the last, the value holds still.
  </Step>
  <Step title="Choose when it plays">
    Pick one or more triggers (below). An animation with no triggers never
    plays on its own, though a plugin can still play it by name.
  </Step>
</Steps>

### When it ends

By default a one-off animation returns the model to its rest pose when it
finishes. Tick **Stay on the last frame** and the model keeps that pose until
another animation plays. Use it for a door that stays open, or for stages
that build on each other.

### Animate with AI

**Animate with AI** writes animations from a sentence, such as "gentle idle
bob, tail sways behind". The result is ordinary keyframes you can edit. Use
**Start from** to have the new animation carry on from the end of an existing
one (**After** that animation) instead of from the base pose, which is how you
build something in stages. It costs about 15 credits.

Edits you make while it runs are kept: the result is merged onto your latest
save.

## Triggers

A model can have several animations, and each can have several triggers.

| Trigger | Plays when |
| --- | --- |
| **On loop** | Continuously, while the model is placed |
| **On placement** | Once, straight after the model is placed |
| **On right click** | A player uses the model |
| **On left click** | A player hits the model (this also makes it unbreakable) |
| **On range** | A player comes within a radius of it (0.5 to 64 blocks) |

How they behave:

- **One animation per trigger.** If two animations both claim right-click,
  the first in the model's list plays. To choose a different one, use the
  **Plays** dropdown on the model's **Get in-game** card when you give it out.
  The choice rides on that item, so two copies of one model can play
  different animations.
- **A playing animation isn't restarted.** Triggering it again while it's
  running does nothing.
- **After a one-off finishes**, the model goes back to rest, or to its looping
  animation if it has one (unless it's set to stay on the last frame).
- **Range fires on arrival.** It plays when someone walks into the radius,
  not every moment they stand in it, and can play again after they leave and
  come back.

<Callout type="note" title="Left click makes a model unbreakable">
  A model with an "On left click" trigger can't be punched to pick it up,
  otherwise the first hit would break it instead of animating it. Give
  players another way to remove it if they need one.
</Callout>

## Playing from a plugin

A server plugin can play any animation by name, including one with no
triggers, which is a good way to keep animations you drive from code from
firing when someone clicks. With RP Engine installed:

```java
RPEnginePlugin engine =
    (RPEnginePlugin) Bukkit.getPluginManager().getPlugin("RPEngine");
if (engine == null) return; // RP Engine isn't installed

for (Placement statue : engine.models().near(altar, 8)) {
    statue.play("Wave");
}
```

You can find placed models near a location (`near`), in a chunk (`in`), or
from a clicked entity (`at`), then `play`, `stop` or ask what's `playing()`.
Call these on the main thread, and remember a model in an unloaded chunk
isn't found. The full API, including listening for clicks on a model, is in
[For plugin developers](/rp-engine/api).

## How playback works

Useful to know when something looks wrong in game:

- When you Sync, the animations go to the server with the pack. RP Engine
  saves them, so placed models keep animating after a restart.
- A placed animated model is several display entities, one per moving part,
  plus one for everything that doesn't move.
- On Java the server updates moving parts ten times a second and the client
  smooths between updates. That keeps a build full of animated props cheap
  for the server.
- The editor and RP Engine use the same keyframe maths, so what you preview
  is what plays.

## On Bedrock

The Bedrock pack carries your keyframes as real Bedrock animations. On a
server with Geyser, RP Engine still decides when an animation plays (same
triggers, same rules), and the player's own client plays the frames, which
looks smoother than Java.

A Bedrock player only sees a placed model once the pack has been applied to
them, because their client draws it from their own copy of the pack.

## Limits

- Animations belong to one model. One model's trigger can't start another
  model's animation, though a plugin can play both.
- Each placed copy remembers which way it was placed, so it animates the same
  way whichever direction you faced.
- Someone who downloads your pack and plays without RP Engine sees every model
  in its rest pose.
