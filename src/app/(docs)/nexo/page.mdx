# Nexo export

The Nexo export is content for a server already running
[Nexo](https://docs.nexomc.com/), not a second resource pack for players to
install. It holds Nexo item and glyph definitions and a normal pack folder.
Nexo reads the definitions, merges the pack folder into the pack it builds,
and serves the result to players.

## Install it

1. In Export, choose **Plugin Support → Nexo**.
2. Unzip the download directly into your server's `plugins/` folder. Do not put
   the zip inside `Nexo/items` or `Nexo/pack`: it already contains those
   folders.
3. Run `/nexo reload all`, then rejoin or send Nexo's regenerated pack to
   players.

The resulting layout is:

```
plugins/
  Nexo/
    items/<your-pack>/items.yml
    glyphs/<your-pack>/glyphs.yml
    pack/external_packs/<your-pack>/
  datapacks/<your-pack>_dialogs/      ← only if the pack has dialogs
```

Give an exported item with `/nexo give <player> <item-id>`. The ids are the
keys in `items.yml`, and the download's `README.txt` lists them along with
everything else it contains.

## What comes across

| In your pack | In Nexo |
| --- | --- |
| 3D model | furniture: hold it, or right-click a block to place it. Its hitbox is measured from the model |
| Vehicle | furniture with the vehicle's seats, so players can sit in it |
| Custom block | a Nexo `custom_block` (note block), mined and dropped like any Nexo block |
| Custom 2D item, 3D item | a Nexo item, keeping its name and the vanilla item a variant is built on |
| Vanilla item in 3D | the vanilla item itself, reskinned for everyone |
| Icon | a Nexo glyph: `<glyph:<pack>_<icon>>` in Nexo text, and `:icon:` in chat |
| GUI overlay | a Nexo glyph, plus a ready-made inventory title (see below) |
| Pause-menu buttons | the redrawn buttons, as in the Java pack |
| Sounds | merged into the pack's sounds, under the event names you gave them |
| Block, item, armour and GUI reskins | vanilla-file replacements in Nexo's pack |
| Dialog | a datapack folder (see below) |

Nexo assigns the item wiring and the note-block state, and writes the number it
picks back into `items.yml`. Do not add one by hand unless you manage your
whole server's allocation.

### GUI titles

Nexo has no menu system of its own, so a GUI overlay is drawn by whichever menu
plugin opens the screen. `README.txt` gives each GUI's title in Nexo's tags,
for example `<shift:-48><glyph:my_pack_gui_shop>`: paste it as that menu's
title.

### Characters are pinned

Every glyph keeps the character ResourcePack AI gave it, written as `char:` in
`glyphs.yml`. That is deliberate: the pause-menu text and the GUI titles already
use those characters, so letting Nexo renumber them would break both. Nexo
assigns its own glyphs from U+A410 upward, so they do not meet.

### Dialogs

Nexo does not install vanilla dialogs, so a pack with dialogs also gets
`datapacks/<your-pack>_dialogs/`. Move that folder into your world's
`datapacks/` folder and restart. Open a dialog with
`/dialog show <player> studio:<id>`. This needs Minecraft 1.21.6 or newer.

## Limits

Some content is drawn by [RP Engine](/rp-engine) while the game runs, and no
Nexo configuration can express it. The README names each one the pack has:

- **Shader objects**: RP Engine sends the text they draw on.
- **3D armour**: RP Engine poses the pieces on the wearer.
- **Animation**: models place as still furniture.
- **Driving**: vehicles place as furniture you can sit in, not drive.
- **Dialog switches and sliders bound to player settings**: they open, but
  remembering a choice needs RP Engine.

<Callout type="warning" title="Vanilla replacements affect every player">
  A block reskin or a screen that replaces a vanilla file is global to the
  resource pack Nexo serves. Remove that file from the exported pack folder if
  you only wanted the custom content.
</Callout>
