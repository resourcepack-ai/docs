# API overview

Everything the Studio does to a pack, your own code can do too: create a pack,
generate blocks, models, items, GUIs, icons and sounds into it, and download
the finished `.zip`.

<Callout type="note" title="On a paid plan">
  API keys are available on any paid plan. Calls spend the same AI Credits the
  app does — there's no separate API pricing and no per-request charge.
</Callout>

## Base URL

```
https://api.resourcepack.ai/api/v1
```

That host serves the API and nothing else. Every path below is relative to it.

## Get a key

<Steps>
  <Step title="Open your account page">
    [studio.resourcepack.ai/account](https://studio.resourcepack.ai/account),
    then find the **API keys** card. It sits just under Bring Your Own Key —
    which is a different thing entirely, and worth not confusing: BYOK is a key
    *you* bring so model generations bill to your OpenAI account. This is a key
    *we* give you so your code can call us.
  </Step>
  <Step title="Name it and create it">
    The name is only for telling keys apart later, so use the thing it's for —
    `ci`, `my bot`, `laptop`.
  </Step>
  <Step title="Copy it immediately">
    **The key is shown once and never again.** We store a hash of it, not the
    key, so there is no way for us to show it to you a second time — if you
    lose it, revoke it and make another.
  </Step>
</Steps>

Keys look like `rpai_` followed by 43 random characters. The prefix is there so
a key that leaks into a commit or a log is easy to search for.

## Authenticate

Send the key as a bearer token:

```bash
curl https://api.resourcepack.ai/api/v1/packs \
  -H "Authorization: Bearer rpai_YOUR_KEY"
```

There's no other way to send it. A key in a query string ends up in access
logs, browser history and `Referer` headers, so it isn't accepted.

<Callout type="warning" title="A key is your whole account">
  It can read, generate into and export every pack you own or collaborate on,
  and it spends your credits. Keep it server-side — never in a Minecraft
  plugin, a browser bundle, or anything you hand to a player. Revoke it from
  the same card the moment you think it's out.
</Callout>

## History

Every key keeps a record of what it did. Press **History** on a key in the
account page to see it: each generation, pack creation and export, with what it
cost.

| Recorded | Not recorded |
| --- | --- |
| Generating anything | Polling a job |
| Creating a pack | Listing packs or assets |
| Exporting a pack | Downloading an asset file |

The split is on purpose. You're told to poll every couple of seconds and a
model takes minutes, so logging every request would bury the four lines that
matter under a hundred saying "still generating".

Credits are the amount **actually settled**, not what was reserved up front —
so a generation that failed and refunded shows no cost at all, and a long model
run shows its real price once it lands.

Revoking a key keeps its history. That's the point: the question after a leak
is what the key did, and deleting the answer with the key would be the wrong
way round.

## Generation is asynchronous

Nothing generates inside a request. A block takes seconds and a model can take
tens of minutes, so every generation endpoint answers **`202 Accepted`**
straight away with a **job handle**, and you poll that handle until it's done.

```
POST /api/v1/packs/{pack}/textures   →  202  { "job": "my-pack:texture:mossy_bricks", ... }
GET  /api/v1/jobs/my-pack:texture:mossy_bricks  →  200  { "status": "generating" }
GET  /api/v1/jobs/my-pack:texture:mossy_bricks  →  200  { "status": "ready" }
GET  /api/v1/packs/my-pack/assets/texture/mossy_bricks  →  the PNG
```

The credit is taken when the job is accepted, not when it finishes, and it's
refunded automatically if the generation fails. See
[Jobs and assets](/api/assets) for the polling detail.

## Errors

Every failure has the same shape:

```json
{
  "error": {
    "code": "insufficient_credits",
    "message": "You don't have enough AI Credits for this."
  }
}
```

Branch on `code`, never on `message` — the wording can change, the code won't.

| Status | Code | What happened |
| --- | --- | --- |
| **400** | `invalid_request` | Something in the body or query is wrong; `message` says what |
| **400** | `invalid_json` | The body wasn't a JSON object |
| **401** | `missing_api_key` | No `Authorization: Bearer` header |
| **401** | `invalid_api_key` | The key isn't one of ours, or has been revoked |
| **403** | `plan_required` | The key is valid but the account is on Starter |
| **403** | `forbidden` | Valid key, but not this action in this pack |
| **402** | `insufficient_credits` | Out of AI Credits |
| **403** | `pack_limit_reached` | Your plan's pack limit |
| **403** | `asset_limit_reached` | This pack's asset limit |
| **404** | `not_found` | No such pack, asset or job — **or one that isn't yours** |
| **409** | `still_generating` | You asked for an asset's bytes before it was ready |

<Callout type="note" title="404 is deliberate for other people's packs">
  A pack you have no relationship with answers 404, not 403 — the same as one
  that doesn't exist. Telling the difference would leak which pack names are
  taken.
</Callout>

## Rate limits

There aren't any. Credits are the throttle: a generation you can't afford is
refused with a 402, and everything else is cheap enough not to meter. Be
sensible when polling — once every couple of seconds is plenty, and a model
won't be done for minutes.

## What's not here

The API covers creating packs, generating into them, and getting assets back
out. It deliberately doesn't cover editing pixels or geometry, iterating on an
existing asset, deleting things, pack settings, collaborators or syncing to a
server — those live in the Studio. If you need one of them programmatically,
say so in [Discord](https://resourcepack.ai/discord).
