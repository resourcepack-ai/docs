# Importing

**Import**, next to **New pack** on the dashboard, turns an ordinary Java
resource pack `.zip` into a pack here, with every texture, model, icon, GUI
sheet and sound it can use opened up for editing.

Import always **creates a new pack**. It never merges into an existing one,
because most of what two packs hold would collide; use
[Moving assets between packs](/moving-assets) afterwards if you want pieces of
it somewhere else.

## How it runs

<Steps>
  <Step title="Pick the zip">
    The zip is opened **in your browser** and nothing is uploaded yet, so
    even a pack of hundreds of megabytes is quick to read.
  </Step>
  <Step title="Review what was found">
    The review screen lists what will come in and what won't, file by file,
    with the reason for each file left out.
  </Step>
  <Step title="Approve it">
    Only now does anything upload. The pack is created and fills in. If you
    cancel partway, Studio asks whether to keep or delete what has already
    arrived.
  </Step>
</Steps>

## What comes in

- **Block and item textures**, including everything outside the curated
  pickers: if the game has a texture by that name, the reskin is accepted.
- **Block models**, with their textures. Models whose faces point at vanilla
  textures come in correctly, referencing the real thing.
- **Icons**, when the pack's font files describe them: the `font/*.json`
  grid is what lets a glyph sheet be split into individual icons. Capped at
  256 per import.
- **GUI sheets** for the screens in our catalog, cut using the known window
  regions.
- **Sounds**, when `sounds.json` names them. The event name is what decides
  whether an `.ogg` replaces the creeper fuse or adds a new sound, so audio
  that no event names is reported rather than guessed at. Capped at 64 per
  import.

**Multi-version packs are handled.** A pack that ships `overlays` for several
Minecraft versions has the overlay matching its own declared version applied
over the base; the base files it replaces are reported as superseded, and the
other versions' trees are set aside rather than mixed in.

## What can't come in

Reported, never silently dropped:

- **Entity, painting and particle sheets.** Their layouts live in the game's
  own code, not in the pack, so there's no honest way to cut them up.
- **Core shaders.**
- **Blockstate and item definition files.** Studio writes those itself when
  it exports.
- **Audio Minecraft can't play properly.** Anything that isn't mono Ogg
  Vorbis: Ogg *Opus* (same extension, silent in game), stereo `.ogg` files
  (which play without position), and other formats.
- **OptiFine extensions.**

## Round-tripping our own export

Importing a pack Studio exported mostly restores it: geometry, textures
and sounds survive. What doesn't, yet: a model's animations, bones and
display settings come back as plain geometry, and per-face block textures
return as ordinary model textures. Keep the original pack around rather than
treating export-import as a backup loop.
