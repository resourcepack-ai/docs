# The plugin

**RP Engine** is our free server plugin. A resource pack on its own can only
change how things look. RP Engine is what makes the rest of a Studio pack
work on a server: models you can place that animate, Emotes, custom screens,
and sending a pack to one player while you test it. [Our test server](/testing/test-server) runs it (the moving models on
<ServerAddress /> are this plugin), and you can put the same jar on your own
server.

<Callout type="note" title="You don't need it to use a pack">
  A pack made here is an ordinary resource pack. Export the `.zip` and point
  `server.properties` at it, with nothing of ours installed. The plugin is for
  the things a resource pack alone can't do, listed below.
</Callout>

## What it adds

| | Without the plugin | With it |
| --- | --- | --- |
| **Models** | The model renders, standing still | Place it, sit on it, pick it up, and it animates |
| **Animations** | Nothing: vanilla ignores the keyframes | Plays on loop, on click, or from your own plugin |
| **Emotes** | Nothing | `/emote` plays one on a player in their own skin, or puts on a movement set they wear while they play |
| **Custom GUIs** | The art ships, but nothing opens a screen with it | `/rp screen` opens the screen with your art drawn over it |
| **HUD overlays** | Same | `/rp hud` draws a meter or a frame over the world |
| **Pack sounds** | `/playsound` works, if you're an operator | `/rp sound` works for anybody, so the person testing can hear their own sound |
| **Live testing** | Re-export, re-upload, rejoin | **Sync** sends a pack to one player in seconds |
| **Distribution** | Host the file and edit `server.properties` by hand | Press **Publish** in Studio and every player gets the new pack |

It also works without Studio at all: items, recipes, entities, liquids and
more, written as YAML in a folder on your server. That half is documented in
[RP Engine](/rp-engine).

## Installing it

<Callout type="note" title="Requirements">
  A Paper, Spigot or Folia server on **1.19.4 or newer**, running **Java 17+**,
  and permission to install plugins on it. 1.19.4 is the version that added display
  entities, which placed models are made of.

  Below 1.21.4 a few things are reduced rather than missing, and the plugin
  prints exactly which at startup. [Minecraft versions](/rp-engine/versions)
  is that list written down.
</Callout>

<Steps>
  <Step title="Download the jar">
    ```
    https://cdn.resourcepack.ai/RPEngine.jar
    ```
  </Step>
  <Step title="Drop it in /plugins">
    Alongside everything else. It has no dependencies and no required
    configuration.
  </Step>
  <Step title="Restart the server">
    `/reload` isn't enough; plugins are only loaded on a full restart. Check
    the console for RP Engine's startup banner: its version, its links, and
    what it loaded.
  </Step>
</Steps>

## Using it

It does two separate things for a pack made in Studio, and a server can use
either without the other:

- **Sync**, for while you build: Studio sends the pack to you (and anyone you
  add), in seconds, with nobody else affected.
- **Distribution**, for when it's finished: every player who joins gets the
  pack.

### Testing a pack on your own server (Sync)

Press **Sync** on a pack in Studio and choose **Testing on your own server
instead?** to get an eight-digit code. Run it in game:

```
/rp sync 12345678
```

This pairs you with the pack. From then on, every press of **Sync** sends
the pack straight to you, without touching `server.properties`.

What Sync sends lasts until you leave. Rejoin, or restart the server, and
you're back to the server's own pack until you press **Sync** again.

| Command | What it does |
| --- | --- |
| `/rp sync <code>` | Pair yourself with a pack in Studio |
| `/rp sync add <player>` | Share your pushes with someone building alongside you (they accept or deny) |
| `/rp sync remove <player>` | Stop sharing with them |
| `/rp sync who` | See who's in your sync |
| `/rp sync leave` | Leave someone else's sync |
| `/rp sync stop` | End your sync |

The `rpengine.sync` permission is for operators by default; grant it to your
builders.

Console commands in a synced pack (a dialog button set to run as the console, a
mob skill using `command`) are only kept when the player who started the sync
has `rpengine.sync.console`, which defaults to operators. Anyone else's push
arrives without them, so granting `rpengine.sync` widely never hands out
console access.

### Giving the finished pack to every player (Distribution)

`/rp distribute <code>` connects the server to a pack from **Distribution**
in Studio. From then on, every player who joins gets the pack, and each time
you publish a new version they get that. See [Distribution](/distribution).

## Commands and permissions

One command, `/rpengine`, with `/rp` and `/rpe` as aliases, plus `/emote` and
`/emotereply` for players. Every argument tab-completes, and every subcommand
has its own `rpengine.<name>` permission with `rpengine.admin` as a parent
that grants the lot.

The full table is on
[Commands and permissions](/rp-engine/commands). Two things worth knowing
before you grant anything:

**`/rp screen`, `/rp hud` and `/rp sound` each take an optional player**, so
granting one lets that person put a screen, an overlay or a sound on someone
else's client. Grant them to the people building your pack, not to everyone.

**Nobody is pulled into an emote without agreeing.** `/emote <name> <player…>`
asks everyone it names first. `rpengine.emote.force` skips the asking, and is
not included in `rpengine.emote.cast`. See [Emotes](/rp-engine/emotes).

## Driving it from your own plugin

Everything above is reachable from Java: place a model, play an emote, open a
screen, put an icon in a message, and cancel any of it when your own rules say
no. See [For plugin developers](/rp-engine/api).
